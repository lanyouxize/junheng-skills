### Phase 4: 双引擎盲测验证

#### Step 4.1: 生成测试短文

写**三段**测试短文：
1. **默认模式**：作者最自然的写法（不指定公式）
2. **公式模式**：选一个"可以驾驭"级别的公式测试边界
3. **思维挑战模式**：选一个作者可能立场复杂/矛盾的话题（如"你表弟买房找你借五万，你借不借？"），测试思维一致性

每段 200-300 字。

#### Step 4.2: 原文对照 + 思维对比

从语料库中随机选取一段原文并排展示。

#### Step 4.3: 盲测分析

```markdown
## 盲测分析

### 测试1：默认模式
| 维度 | 原文特征 | 仿写表现 | 匹配度 |
|------|---------|---------|--------|
| 词汇 | ... | ... | ⭐⭐⭐ |
| ... | ... | ... | ... |

综合匹配度：XX%

### 测试2：公式模式（[公式名]）
公式模式综合匹配度：XX%

### 测试3：思维一致性测试（[挑战话题]）
| 检查项 | 评估 |
|--------|------|
| 立场是否符合作者的价值观？ | ✅/⚠️/❌ |
| 情绪反应是否符合作者的情绪触发点？ | ✅/⚠️/❌ |
| 论证方式是否符合作者的思维习惯？ | ✅/⚠️/❌ |
| 如果是原作者看这段，他会点头还是摇头？ | [判断] |

### 像的地方 | 不像的地方 | 改进建议
...
```

**匹配度判断**：
- 90%+：出口即是，基本不需要调整
- 70-89%：核心特征抓住了，细节有偏差
- 50-69%：大致方向对了，但辨识度不足
- <50%：需要回到 Phase 2 调整风格画像

#### Step 4.4: 质量自检

生成分身后，执行质量自检。检查以下6项标准：

| 检查项 | 通过标准 | 不通过信号 |
|--------|---------|-----------|
| 思维基因数量 | 3-5条，每条有思维层面+写作层面映射 | <3或>7 |
| 每个基因的局限性 | 明确写出失效条件 | 只写优点 |
| 写作风格辨识度 | 读100字能认出是谁 | 像通用模板 |
| 诚实边界 | 至少3条具体局限（语料限制、时效性、盲区） | 只有「不能替代本人」 |
| 内在张力 | 至少2对矛盾 | 观点高度一致（太假） |
| 信息来源占比 | 一手文章文本 >80% | 主要依赖推测 |

验证通过 → 进入Phase 5精炼。不通过 → 标注薄弱环节，回到Phase 2迭代。
**迭代上限**：Phase 2→4最多循环2次。如果2轮后仍有不通过项，在诚实边界中标注薄弱维度，交付当前最优版本而非无限打磨。

**展示验证结果给用户确认后才算完成。**

### Phase 5: 双Agent精炼（标准后置工序）

Phase 4 验证通过后，自动启动双Agent精炼，进一步提升分身可操作性：

**并行启动两个Agent：**

**Agent A（使用者视角）**：
- 对分身技能SKILL.md执行6维度可用性评估（写作铁律清晰度、思维约束可操作性、检查点设计、指令具体性等）
- 干跑3个典型写作prompt，评估效果维度
- 输出：最弱2个维度的具体改进建议（要有改后文本示例）

**Agent B（skill-creator视角）**：
- 评审「触发条件」是否覆盖真实使用场景
- 评审「双重复检系统」的可操作性（复检一指纹覆盖率、复检二思想匹配度、失败重写路由）
- 识别缺失的关键信息
- 输出：2-3处具体文本改动建议（要有改后文本示例）

**主Agent综合两份报告，应用不冲突的改进，展示变更摘要请用户确认。**

精炼标准：改动必须让分身「激活即执行」，不只是增加内容，而是让AI拿到分身后知道先做什么、碰到什么停下来。

## 更新已有分身

当用户说「更新XX的分身」「XX最近有新文章」时：

1. 读取现有分身技能 SKILL.md，从「诚实边界」section中找到「分析时间：[日期]」，标注距今多久
2. 只分析新增文章（Phase 1 双引擎分析，但只针对新文章）
3. 对比新信息与现有内容：
   - 新信息强化现有基因 → 补充案例
   - 新信息与现有基因矛盾 → 标注变化，更新基因
   - 出现新的思维/写作特征 → 考虑增加新基因
4. 更新SKILL.md中的「最新动态」section和分析时间
5. 不重写整个分身，只增量更新

## 特殊场景处理

### 场景1：素材太少（<3篇或<2000字）

- 不拒绝，但明确告知风险："素材太少会导致风格画像不完整。建议至少3篇2000字以上。如果继续，生成的写作分身可能只能覆盖该作者的部分特征。"
- 生成时标注："⚠️ 语料不足，本写作分身仅基于N篇文章共XXX字分析。可能存在遗漏。"

### 场景2：文章类型混杂

如果用户提供的文章涵盖不同类型的写作（如既有故事文又有评论文）：
- 分析时标注"风格分离"：区分不同类型文章的不同特征
- 生成时让用户选择："该作者在故事和评论两种类型中风格差异较大，你要蒸馏哪种风格的写作分身？"

### 场景3：同名不同人的文章

如果怀疑素材来自不同作者（如一个公众号有多个写手）：
- 在 Phase 0 就标注出风格不一致的信号
- 提醒用户："这些文章的风格差异较大，可能不是同一个人写的。你确定这些是同一个作者吗？如果是团队创作，蒸馏出来的可能是一个混合风格。"

### 场景4：更新已有分身

如果用户之前已经蒸馏过这个作者，现在有了新文章：
1. 读取现有的技能 SKILL.md
2. 只分析新增文章
3. 对比新旧发现：新信息强化了哪些特征？改变了哪些？
4. 增量更新技能，而不是重写

### 场景5：蒸馏自己的文章

如果用户说"蒸馏我自己的文章"：
- 素材摄入流程相同
- 生成提示词时，身份描述用"你就是你自己"而非"你是[作者名]"
- 额外注意：帮助用户发现自己可能没意识到的写作习惯

### 场景6：中国作者 vs 西方作者

- **中国作者**：信息源优先级：公众号文章（用户直接提供）> 小红书/微博 > 权威媒体采访（36氪/晚点/财新/虎嗅）。知乎和百度百科永远排除
- **西方作者**：信息源优先级：本人博客/Medium > Twitter/X > 权威媒体采访

### 场景7：冷门作者（公开信息极少）

当Phase 0.3评估后发现可用文章<3篇时：
1. 在Phase 0.3就告知用户"这个作者的公开文章很少，生成的分身质量会受限"
2. 思维基因减至2-3条，每条都标注「基于有限信息推测」
3. 诚实边界section加大篇幅，明确列出「哪些维度信息不足」
4. 如果用户能提供一手素材（私人文章、邮件、笔记），优先使用

### 场景8：主题风格蒸馏 vs 作者风格蒸馏

输入不是单个作者而是主题（如"小红书爆款文风""知乎高赞回答风格"）时，各Phase变体：

| Phase | 作者风格蒸馏 | 主题风格蒸馏变体 |
|-------|----------|--------------|
| 0A | 确认作者名+题材 | 确认主题边界+目标平台（"小红书爆款"是美妆还是数码？） |
| 1 | 双引擎分析单个作者 | 先搜索该主题的3-5个典型作者，再按作者分配分析（每人1-2个维度而非9个） |
| 2.1 | 提取一个人的思维基因 | 提取**主题共识特征**（所有作者都有的）+ **作者分歧**（A说X，B说Y） |
| 2.5 | 提炼个人思维基因 | 不提炼思维基因，改为提炼**主题风格基因**（如"标题必须制造好奇缺口"） |
| 3 | 用 persona-template.md | 调整模板：去掉思维画像和身份卡，改为「风格概览」+「平台特性」 |
| 4 | 对比此人已知文章 | 对比主题内公认的典型文章 |

## 品味守则

| 原则 | 一句话 |
|------|--------|
| **多篇 > 单篇** | 10篇比1篇更能揭示真正稳定的风格特征 |
| **习惯 > 偶然** | 反复出现≥3次的才是真特征，只出现1次可能是即兴发挥 |
| **矛盾有价值** | 发现作者在不同文章中的不一致写法时，不要强行调和——保留矛盾 |
| **具体 > 抽象** | "喜欢用短句"没用，"平均句长12字，30%的句子少于8字"有用 |
| **否定 > 肯定** | "他从不做什么"往往比"他做什么"更能定义风格边界 |

### 绝不做的事
- 凭空猜测作者的背景或动机（只基于文本分析）
- 把通用写作技巧包装成该作者的"独门秘笈"
- 忽略文章中的不完美和不规整（那些恰恰是最有区分度的特征）
- 在语料不足时强行生成"完整"的风格画像

## 与现有技能的协作

- **human-story-writer**：如果蒸馏的是故事型公众号作者，可参考其44条反AI规则的思路来生成禁用清单
