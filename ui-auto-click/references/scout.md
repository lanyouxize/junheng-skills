# 微信「赞和收藏」逐篇发现（scout）

## 微信「赞和收藏」逐篇发现（scout）

自动遍历「我已点赞」的文章，**从上到下、每轮只处理一篇**；仅当该篇所属公众号
**尚未采集过**时才点击，否则跳过。设计与取证过程见
`references/wechat-favorites-flow.md`。

### 为什么不能用控件树

微信 PC 4.x 是 CEF/Chromium 自绘 UI。本机用 **UIA 与 MSAA 两个独立后端**验证：
都只能看到 Chromium 框架视图和三个原生标题按钮，真实界面（个人中心 / 赞和收藏 /
文章列表）完全不可见，也没有远程调试端口。
⇒ 只能走「截图 + 模板匹配 + 坐标点击」。**所以本流程不依赖 `clicker.py` 的步骤表**，
那套 UIA 动作只对 PySide6 写的下载工具有效。

### 三步用法

```bash
PY="C:/Users/Administrator/.workbuddy/binaries/python/envs/default/Scripts/python.exe"
SK="C:/Users/Administrator/.workbuddy/skills/ui-auto-click"

# ① 校准（前提：微信停在「赞和收藏」页，且不被其他窗口遮挡）
"$PY" "$SK/scripts/capture_templates.py"

# ② 只决策不点击，先看判据是否符合预期
"$PY" "$SK/scripts/wechat_favorites.py" --dry-run

# ③ 真跑（每轮一篇；默认返回键 ctrlw＝关闭文章 tab）
"$PY" "$SK/scripts/wechat_favorites.py"                      # 1 篇
"$PY" "$SK/scripts/wechat_favorites.py" --max-rounds 5       # 连续 5 篇
```

接进流水线：`pipeline.py` 新增 `scout` 阶段，插在 `preflight` 之后、`download` 之前
（先发现新号，再下载）。可用 `--skip scout` 跳过，或 `--scout-dry` 只决策。

**交接约定（2026-10-23 修）**：下载工具的「1.获取公众号id」要求微信里**正开着**该号
文章，否则日志只刷「请先在左面打开微信内置浏览器」。所以 `stage_scout` 固定传
`--return-key none`，点开后**不**关 tab，把文章页留给 download；`--from-step download`
才需要人工先把文章页开着。

**已知缺口**：实测工具真正吃的是「微信文章链接」框里的**可访问文章 URL**（留空时点
「1.获取公众号id」没有任何日志）；而 scout 只点击、不复制链接。补齐方向（按代价升序）：
① 人工把链接粘进框里再 `--from-step download`；
② 加 `--article-url` 参数，由调用方（如 L1 采集到的链接）传入；
③ 在文章页自动「…→复制链接」（CEF 页面需图像坐标，成本最高）。

### 三个判据

| 判据 | 实现 | 阈值 |
|---|---|---|
| 在「赞和收藏」页 | `page-title.png` 全图匹配；回退 `tab-all.png` + 实时检出 ≥2 行 | ≥ 0.80；回退判据**真正的判据是 rows**——`tab-all` 在「关注·最近更新」消息流页也能到 0.9652 |
| 这篇属于哪个公众号 | 行内**文字带投影**定位账号行 → 二值化**列投影指纹**比对候选名单 | ≥ 0.70 **且** 领先第二名 ≥ 0.20 |
| 该号是否已采集 | 下载根目录子目录名 + 各 `manifest.json` 的 `account` 字段，**每轮重读** | 命中即 skip；同号多行另按账号指纹拦截（≥0.85） |

第三个判据**不需要改代码**：新增一个采集目录，名单自动增长。

第三个字段之外，还有两条工程细节值得记住：

- **行不能按缩略图找**。行 = 标题（深墨）+ 紧随其后的灰色账号名（整带无深墨）。
  按"彩色缩略图块"找行时，黑图/灰图缩略图的行整段漏检——同一张收藏页 10 行
  只检出 3 行（真实事故）。左界靠列墨量排除「合集/赞和收藏」标签栏。
- **左界要在页面下半部统计**。标签栏只有 5~6 行、且顶部；一旦某个标签被选中
  （圆角底色块 + 深色文字），整页列墨量会把左界拉进标签栏（实测 262，正确 420）。
  后果是条目 1 的账号带混入「赞和收藏」四个深墨字而被判"非账号带"——
  **第 1 条永远不点**，而检出结果只是"从第 2 条开始数 10 行"，行数看着正常。
- **返回列表必须 Ctrl+W**。微信 4.x 文章页是主窗口内嵌的 CEF tab，Escape 与
  Alt+Left 实测都无效（会卡在 `scout.return_failed`）；`vision.close_tab()` 1.5s 内恢复列表。
- **同号判定有真机数据**：同号指纹内积 0.895~0.994，不同号 -0.12~0.37，阈值 0.85
  余量 ≥0.52。改账号名字号/透明度后要重测 `ACCOUNT_SAME_MIN`。
- **改行检测算法后**：① 重算 `out/wx-rows.json`；② journal 里旧 `algo` 的指纹会
  失配（那几篇会被重复点一次），启动时会打 `scout.fingerprint_algo` 告警。
- **截图前必须把光标挪出行**（`vision.park_cursor`，`_capture` 里统一做）。列表行
  有 hover 态：鼠标压在某行会让该行 dHash 变（`0110…→0111…`），而行几何
  `y1/y2` 一字不差 ⇒ 靠坐标查不出来，只会表现为"同一篇被重复点"。
- **账号行不能按坐标猜**。位置必须从文字带量出来：纯灰（160）、整带无深墨、
  字高小于标题。按"行中心 ± 固定偏移"猜在标题换行行上会框到标题，结果是
  识别分恒 0.0、账号去重静默失效。定位失败时必须**打告警**再兜底。
- **识别必须看余量**。「宠物食品联盟」和「宠物食品商情」前四字相同，指纹分只差
  0.008 —— 只设绝对阈值会把新号误判成已采集（漏采）。余量不足一律判未知、按新号点。
- **同号只点一篇，名单每轮重读**。已采集名单是目录扫描，启动读一次会变成过期快照
  （点完第一篇时下载侧还没落盘）；`--max-rounds>1` 时"同号占多行"要在**会话内**按
  账号区域列投影指纹（内积 ≥0.85）拦截，不能等名单增长。跳过一行后必须把该行指纹
  记进内存，否则每轮重评同一行、原地打转。

### 模板证伪测试（必做）

模板错了，下游全部假阳性。实测踩过：错误坐标截的"页面标题"模板实际框到
Windows 设置的搜索框，导致遮挡检测对干净微信和被压住的微信都返回 1.0 分。

每个模板必须**同时**满足三条（判别余量）：目标页 ≥ 0.80 **且** 最差无关画面 ≤ 0.80
**且** 两者相差 ≥ 0.25，否则不写入 `templates/`。第三条是关键——早期写"无关画面
≤ 0.50"会把 tab-all 误杀（它对聊天页 0.533，但余量 0.47 足够大，是好模板）。

负面样本：`out/wx-negative.png`（被压盖）+ `out/wx-negative-chat.png`（聊天页）。

### 关键约束

- **每轮最多点一篇**：点击后离开列表页，跨轮坐标指代会失效。
- **点击前必须重新截图并校验**：截图是合成桌面，压盖窗口会让坐标点错。
- **先离页再认页**：点击后等列表信号消失 → **Ctrl+W 关闭文章 tab** → 等信号恢复；
  点完立刻判定"还在列表页"会误以为没打开而重复点击。
- **行指纹取文字区**（窗口左沿 → 缩略图左沿），`dhash(size=16)`；含缩略图时实测
  10 行只出 9 个唯一值 ⇒ 撞指纹 ＝ **静默漏采**（点了 A 行，B 行被当已处理）。
  journal 里已点过的行不再点；`--dry-run` 只写 `would_click`，否则一次预演会让后续
  真跑全部跳过。
- **最小化哨兵 rect 必须拒绝**：GetWindowRect 在最小化时返回 -32000 附近，宽度
  高度都非零，能骗过"rect 为零"的判据，拿它算坐标会点到屏幕外。
  `vision.capture_window` 统一拒绝（`is_sentinel_rect`），scout 先用 `vision.is_iconic`
  补一条可操作告警。
- **选窗只有一条路径**：`vision.py shot/rows/occl`、`grab_wechat`、scout 全部走
  `vision.wechat_window()`（CEF 类名优先）。曾经 `shot` 用 `find_windows("微信")[0]`，
  会选中标题带「微信」字样的浏览器窗口——拍出来的证据图与 scout 看到的不是同一扇窗。
- **不新增第三方依赖**：只用车载的 pillow / opencv-python-headless / numpy / pywinauto。
  环境里没有 OCR 二进制，Windows 内置 WinRT OCR 又因安全策略禁止运行时加载程序集而
  不可用，所以用「账号行指纹比对」替代。
- **阈值偏向"认不出来就当新号"**：假阴性代价是重复下载（下游幂等去重），
  假阳性代价是直接漏采。
