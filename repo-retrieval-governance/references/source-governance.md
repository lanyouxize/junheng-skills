# 源头治理：让它不再长出来（2026-09-20 立）

## 七、源头治理：让它**不再长出来**（2026-09-20 立）

> §三 / §六 都是**事后清理**。清理一次不够 —— 只要产生它的习惯不变，下个月堆回来。
> 本节治的是**上游**：让污染不再产生。

### 7.1 唯一病根：老规矩只规定了「动作」，没规定「落点」

原规矩（`MEMORY.d/04-工程硬约束.md` · 批量改码三件套 ①）：

> 「每个待改文件先 `cp` 成 `.bak_<标识>`，零删除」

它规定了**要备份**，但**没说备份放哪** ⇒ 落点就默认成「源文件旁边」（最顺手）。
⇒ **这不是谁偷懒，是规矩本身留了个洞。** 修法是**改落点，不改动作**（退路必须有，只是不许留在原地）。

### 7.2 新规矩：「备份不留原地」（全项目生效）

| 集合 | 备份落点 |
|---|---|
| 项目仓 `<repo>/` | `<repo 同级>/<repo>-artifacts/change-backup.<YYYYMMDD>/` |
| 用户级 `~/.workbuddy/` | `~/.workbuddy/_archive/change-backup.<YYYYMMDD>/`（见 7.5 例外说明） |

工具（**别手搓 `cp`**）：`python ~/.workbuddy/scripts/safe_backup.py <文件...> [--tag 说明]`

| 参数 | 作用 |
|---|---|
| （默认） | copy 到归档区；**同日同文件已备份 ⇒ 跳过**，留最早的「动手前原样」 |
| `--check` | 只报落点，并**直接报红**「归档根落在集合树**之内**」 |
| `--dry` | 只出计划不写盘 |
| `--list` | 列已备份批次（含 count/bytes） |
| `--restore <批次> [--file <rel>]` | 回迁；覆盖前先把**当前版本**另存 `pre-restore.<ts>/` |
| `--retire <通配...>` | **退休模式（mv-only）**：把污染检索面的东西**搬出集合树** + 留清单可回迁；落 `<repo 同级>/<repo>-artifacts/retired.<日期>/`。**这就是「归档」的标准动作**，别再手搓脚本 |
| `--stamp <名>` | 显式另起一批（刻意保留中间态时才用） |

**为什么"同日跳过"就是对的**：备份的语义 = 「**动手前的原样**」。
一天内反复改同一文件 N 次，要回滚的那个状态**只有一个** —— 最早的原始版。
⇒ 跳过既保住语义、又天然不膨胀（一天一批、一文件一份）。

### 7.3 备份义务分级（别从一个极端跳到另一个）

| 动作 | 备份 |
|---|---|
| 单文件精确替换（Edit，`old_string` 自带原串） | 不必（原串本身就是记录） |
| **批量正则 / 脚本改写**（一炸一片，实测炸过 70 个文件） | **必须**，改前 |
| 删 / 移 / 重命名 / 覆盖 / 格式化 | **必须** + 清单 |
| 改**别人给的原始资料**（发票、源素材、客户件） | **必须** |
| 仓内有 git 且工作区干净 | git 兜底即可；要用额外备份也走 7.2 落点 |

### 7.4 三处「看起来该清、其实不能动」（2026-09-20 实测）

| 位置 | 结论 |
|---|---|
| `workspace/sessions/*/modify_backup*/`（实测 **1571 个 `.bak` / 10.3 MB**） | **平台自己的编辑备份机制**，不是我们的习惯产物 ⇒ 不动（该目录整体 2221 MB / 203204 文件，属平台数据） |
| `plugins/cache/**/*.miora-hidden.bak`、`binaries/**/node_modules/**/*.bak` | **第三方 / 官方插件自带** ⇒ 不动 |
| `MEMORY.md.bak_20260901_1530` 这类「拆分前的原文件完整备份」 | **有保留价值** ⇒ 归档不删（`mv` 进 `_archive/`） |

### 7.5 判断「是不是自家产物」的一句话判据

> **它是不是我们自己写的、或我们改出来的？** 不是 ⇒ 不动。
> 别把「看起来像垃圾」当「可以清」 —— 这是本 skill §三 已经证伪过一次的直觉。

> ⚠️ **唯一允许"在树之内"的例外**：`~/.workbuddy` 是用户级配置根，外面没有合适落点 ⇒ 归档到它自己的 `_archive/`。
> 这一点**明写、不藏**：它是"约定的内部归档区"，不是"真在外边"。

### 7.6 回迁可用性必须能被证明（2026-09-20 修 · 第 4 个洞）

**症状**：某批次清单是**带 BOM 的 JSON**（人手写的 / 别的脚本落盘的），
而 `safe_backup.py` 三处读清单都写死 `encoding='utf-8'` ⇒

| 入口 | 原来的表现 |
|---|---|
| `--restore` | **直接抛 `JSONDecodeError: Unexpected UTF-8 BOM` 崩掉** |
| `--list` | 被 `except: pass` 吞掉 ⇒ **静默显示 `count=0`**（看起来这批是空的） |
| 写入侧 `do_backup` | `except: pass` ⇒ 读不出旧清单就**只写新条目、把旧清单覆盖掉** |

★ 第三条最险：manifest 是备份的**索引**，**索引丢了 = 那一批等于不存在** ——
而「备份过」这件事在日志里**照样是绿的**。

**修法**：① 读清单统一走 `_load_manifest()`（`utf-8-sig`，有 BOM / 无 BOM 都能读）；
② `do_backup` 读不出旧清单 ⇒ **拒绝覆盖并报错中止**，不许静默重建；
③ `do_list` 读不出 ⇒ **打印 ⚠ 并注明异常类型**，不许静默 0。

**纪律（比修法更值钱）**：**「备份好了」不是证据，「能回迁」才是** ——
凡管回迁的工具，**装上当天就要有一条能证明「回迁真能用」的负例自测**。
配套：`python ~/.workbuddy/scripts/selftest_safe_backup.py`（**11 项**，含 BOM / 正反斜杠 / 损坏清单 / retire / `--again` 五类负例）。

> 同源洞察：`--file` 严格相等匹配、集合根上溯过头，也是**同一批「首次真用才现形」**的洞 ——
> 见 7.2 与 `lesson_gate.py file` 的「新脚本第一次真用必当一次正式验证」。

### 7.7 归档 = 一条命令（2026-09-20 立 · 第 4 次重复后不再手搓）

**为什么立**：同类「把污染搬出树」的动作已经手搓 **4 次** ——
`~/.workbuddy/skills` 的 42 份 `.bak` / `dist/*.bak_*` 14 个目录 / <your-company-workbench> 的 106 份 `.bak` /
项目日记里的 38 份 `.bak`。**每次都要现写脚本、现想清单格式** ⇒ 规范和落点都会漂。

```bash
"<managed python>" ~/.workbuddy/scripts/safe_backup.py --retire "<通配...>" --tag "说明"
"<managed python>" ~/.workbuddy/scripts/safe_backup.py --retire --dry "<通配...>"   # 先看搬哪些
```

| 特性 | 说明 |
|---|---|
| 模式 | **mv-only（只移不删）**，与 `do_backup` 的 copy-only 严格区分 |
| 落点 | `<repo 同级>/<repo>-artifacts/retired.<YYYYMMDD>/`；用户级走 `~/.workbuddy/_archive/` |
| 清单 | `_manifest.json`：`mode / root / source / dest / count / bytes / entries[{rel,bytes,src,dest}]` |
| 幂等 | 归档区已有同路径 ⇒ **跳过**（不报错、不覆盖） |
| 通配 | **工具自己展开** `*` `?`（本机 Git Bash shim 残缺，交给 shell 不稳）；展不到就原样保留 ⇒ 报「不存在」而不是静默什么都不做 |
| 顺序铁律 | **先能读通旧清单，再动手** —— 读不出就拒绝覆盖；反过来写会「文件已搬走、索引没更新」= 现场半成品 |
| 自测 | `selftest_safe_backup.py` T9–T12（只移不删 / 幂等 / 损坏清单动手前拒绝 / `--again` 同日第二份快照） |

### 7.8 拆文件后的零丢失校验（配套 7.7 的兄弟动作）

退休讲「搬走不丢」，**拆文件**同样要证：`split_verify.py` 拿原文件逐行做指纹，
要求每条实义行都能在「主文件 + 外置目录」里**逐字找到**。

```bash
"<managed python>" ~/.workbuddy/scripts/split_verify.py --src <原文件> --dst <主文件> <外置目录>
```

- 判据：**实义行（去空白后 ≥6 字、非纯分隔符）100% 命中**才叫零丢失。
- 有意修改的少数行会如实报「缺失」⇒ **人必须逐条解释**（本次 HABITS 拆分：122/127 逐字命中，
  5 条缺失全部是「标题 / 开工自检 / 三层铁律 / 拆分口径 / 工具清单」的**增量补写**，无一处删除）。
- ⚠️ **别拿「我读过原文」当证据**；也别只数行数（09-18 血账：断言选错量）。

### 7.9 拆出去的东西必须仍在「两个视图」里（本次最险的一条）

| 视图 | 漏了会怎样 |
|---|---|
| **搜索面**（`memory_search.py`） | 主文件里的指针还在、**正文搜不到** ⇒ 「搬走 = 丢掉」最隐蔽的形态 |
| **体检表**（`memory_audit.py`） | 拆完从体检里消失 ⇒ 观感上和删掉没差别，还看不出它胖不胖 |

⇒ **新建任何 `*.d/` 外置目录之后，两件事必做**：① 搜索面自动收纳（按 `SKDATA.glob('*.d')`，
不写死名单）；② 体检表把它列出来（阈值按「按任务现取」放宽，但仍**必须可见**）。
**闸门**：`selftest_memory_search.py` 的 T1 守①（负例证伪过：拿掉 `.d` 搜索面 ⇒ 8/8 缺失 ⇒ 红）。
> 同理，§六 表里"用户级 skills → `~/.workbuddy/_archive/`"沿用同一例外。

### 7.10 检索器的两种「说谎」：假绿与假红（同族，根都是**结果语义没分清**）

| 形态 | 现象 | 后果 | 修法 |
|---|---|---|---|
| **假绿** | 外置块不在搜索面 ⇒ **指针还在、正文搜不到**；验证方式是「搜个词有命中就算通」，命中的其实是**指针那一行** | 「搬走 = 丢掉」 | 搜索面自动收纳 + **覆盖性断言**（比「实际扫描集合」）＝ T1 |
| **假红** | `memory_search.py "甲 乙"`（引号）＝**一个含空格的整串**，必然 0 命中；头部却打印成 `关键词: 甲 乙 [AND]`，与「两词 AND」**长得一模一样** | 「0 命中」被误读成「**记忆里没有**」⇒ 跑去**重写一条已存在的记忆**（比漏检更贵的二次浪费） | 默认按空白**拆词**（与头部口径一致）+ 显式 `--phrase` 走整串 ＝ T8 |

**通行判据**：**输出里的「命中 0」必须能让用户区分是「真没有」还是「查法错」** ——
区分不了就等于给了个会误导人的判据。**先修判据，再修被测对象。**

### 7.11 判据会「**自噬**」：判据的措辞污染判据的输入（★ 2026-09-20 第 3 轮）

**现象**：给体检器做「通用锚点识别」时，第一版是 `t.find('## 📄 悬决项详情')` ——
只要正文里**出现这个字符串**就算锚点。结果两个数字明显不对：
我加过速览的文件读取面被判成 **235 字**（真值 4,121）；`MEMORY.d/04` 从 18,432 被截成 **15,659**。

**根因**：这两份文件**正文里逐字写着锚点的名字** —— `MEMORY.d/04` 写着
「速览锚点（`## 📄 …详情` / `## 📚 全量流水账`）」（**它在解释判据**），
给外置块加速览时也提了锚点名 ⇒ **判据命中了那句「提及」**。

**为什么比一般的错更坏**：
| | 错法 | 表现 | 会不会自曝 |
|---|---|---|---|
| 第一次 | 锚点**按文件名写死** ⇒ 外置块认不出 | 读取面 = 全文 ⇒ **拆了白拆**（偏严） | **会**（一直报 🟡，有人会去查） |
| 第二次 | `find` 命中**正文那句提及** ⇒ 读取面被截短 | **越错越「绿」**（偏松） | **不会**（全绿，看起来一切正常） |

⇒ **判据的错要按「会不会自己暴露」分级**：**会变绿的错，必须配一个专门喂坏样本的测试**。

**修法**：**锚点是「标题」，不是「字符串」** ⇒ **行首匹配**（`\n## …` 或文件开头）。
**闸门**：`selftest_memory_audit.py`（**6 项**）—— T2「只有正文提及 ⇒ 读取面必须 = 全文」、
T3「提及在前、真标题在后 ⇒ 按**真标题**算」（实测 3,547 vs 若错则 546）。

**通行纪律**：凡「在文本里找某个标记」的判据，**先问一句「这个标记名会不会出现在正文里」**
（**中文项目里文档特别爱解释自己**）；解法一律是**行首 / 结构化匹配**，不是 `in` / `find`。
> 同族血账：09-04「**检测脚本会命中自己**（示例里含敏感字面量）」
> —— **判据生活在它自己描述的世界里。**

### 7.12 同日**幂等**备份 = 同日第二次改动**没有独立退路**

`safe_backup.do_backup` 对同一文件同一天**幂等**（「已有更早备份，跳过」，保留最早那份）。
防膨胀是对的，但副作用是：**当天的快照停在「第一天第一次改动之前」**，
而第二次改动**看起来像备份过了**（输出只有一行 `↷`，混在正常流程里，人不会注意）。
⇒ 纯追加型改动无所谓（快照 + 追加内容可反演），**破坏性改动就是真缺口**：
你以为有退路，退路里却没有你刚改的基线。

**修法**：`--again` ⇒ 另起批次 `<日期>-<时分秒>`；`selftest_safe_backup.py` **T12** 守。
**通行判据**：**「备份过了」要能指出「哪一份、什么时候、改前还是改后」** —— 指不出来等于没有。
> 同族：§七「备份不留原地」（那份讲**落点**，这条讲**同日重复**）。

### 7.13 退休之后必须**核验**：`verify_retire.py`（★ 2026-09-20 第 4 轮 · 第 4 次手搓后工具化）

**「只移不删」只是动作** —— 能证明「零丢失」的只有两组证据：

| 组 | 查什么 | 判据 |
|---|---|---|
| ① 结构 | manifest 条数 vs 归档件数 | 相等；`mode=mv-only`；`src` 已不存在、`dest` 都在位 |
| ② **通路** | 归档件**在不在 `memory_search` 的实际扫描面里** | 归档目录在 `cold` 面内 **且抽样真能端到端捞回** |

**为什么 ② 是命门**：缺 ② 时「归档」= **从视图里消失** = 等于删除，
而**体检 / `--list` / manifest 全都显示正常**，没人会知道。

**实测（第 4 轮抓到的第 2 个藏身处 ——「后缀」）**：
`_iter_files` 判「是不是文本」用的是 `Path(name).suffix in TEXT_EXT`，
而归档的**改前快照**叫 `2026-09-18.md.bak_b132p2` ⇒ 后缀是 `.bak_b132p2` ⇒ **整类文件永不被扫描**。
证据：`2026-09-16-15-33-12` 归档 **8 件，只有 1 件**进 cold 面（另 7 件已「退休」但搜不到）。
**修法**：判据改成「**剥掉 `.bak*` 尾巴之后**是不是文本后缀」；
**闸门**：`selftest_memory_search.py` **T9**（已负例证伪：恢复旧判据 ⇒ 判红，缺 `b.md.bak_b132p2` / `c.md.bak_20260920`）。

**通行纪律**：凡「**按文件名 / 后缀筛文件**」的判据，
**先问一句「归档 / 备份 / 快照类文件叫什么名字」** ——
**它们永远是筛子的漏网形状**（`.bak_<tag>` / `.orig` / `.old` / `~$` / `.dist` / `.rejected` …）。

```bash
"<managed python>" ~/.workbuddy/scripts/verify_retire.py 2026-08-18-16-42-57 2026-07-26-15-30-55 …
# 也可直接给批次目录：<你的工作区根>/<工作区名>-artifacts/retired.<日期>
```
> ⚠️ 它自己第一版就错了（**假红**）：**先删字符、再截 20 字窗口** ⇒ 截出来的是
> **原文里根本不存在的串** ⇒ 5 个批次全判红。教训：取样必须保证「**逐字连续存在于原文**」，
> 且**多取几个样本、任一命中即通过**（防「套话占满命中额度」）。
