# 上手实操：怎么在对话里安全地动 OOXML

主 SKILL.md 讲的是「为什么」，这份讲「怎么做」。当用户丢来一个 `.docx` 让你读/改/查修订时，按这里的方法走。

## 0. 先弄清你要做哪件事

| 你想做什么 | 用哪条路 | 别做成 |
|---|---|---|
| 快速看内容 | 结构化抽取（见下） | 直接解 xml 一顿乱改 |
| 新造一个文档 | 样式驱动生成 | 手拼一堆直接格式 |
| 改一个被审过/复杂的存量文档 | OOXML 感知编辑 | 整段重写 paragraph |

**先告诉用户你要用哪条路**，尤其 `改存量被审文档` 默认走审阅式最小替换。

## 1. 把 .docx 当 zip 看（读取前）

`.docx` 就是 zip。改了之前先看包结构：

```bash
unzip -l 目标.docx        # 列出所有部件，先看有哪些
unzip -p 目标.docx word/document.xml > /tmp/body.xml
```

- 脚本/工具处理时，用你熟悉语言的 zip / OOXML 库来读写入，别手写正则去拆 XML 大文本。
- 深改前**先看全场**（document.xml 有多长、有没有 styles/numbering/headers/footers 部件），别只信渲染。

## 2. 结构化抽取（读因为要理解）

目的：把可见文字、表格、段落关系抽出来看，不碰原始结构。

- 抽取时把 **`<w:p>`（段落）、`<w:t>`（文字 run）、`<w:tbl>`（表格）** 作为主要单元。
- 一段话常常跨多个 `<w:t>`，抽取时要按段落拼，不要按单个 run 输出，否则会看到「断成几截」的文字，误以为内容损坏。
- 表格别只抽 `<w:t>` 拉平成一段——保留单元格 `w:tr` / `w:tc` 的层级再读。

## 3. 样式驱动生成（新造文档）

- 优先**命名样式**（引用 styles.xml 里定义好的段落/字符样式），不要逐段堆 `<w:rPr>` 直接格式。
- 想要沿用某种风格：找到已存在的 style id 用，别抄另一个文档的样式节点来（会带进主题、编号定义）。
- 需特定页面尺寸：在 `<w:sectPr>` 里显式写 `<w:pgSz w:w="..." w:h="..."/>`（A4: 11906×16838 twips；Letter: 12240×15840）。别靠默认。

## 4. OOXML 感知编辑（改存量/被审文档）

- **先查有没有修订**：`document.xml` 里找 `<w:ins>` / `<w:del>` / `<w:commentRangeStart|End>`。
- 有修订：**只改目标片段**，把编辑包进 `<w:ins>`，删除用 `<w:del>` 结构，别把整段原文抠掉重写。
- 批注、脚注、书签、超链接的锚点/关系别带丢：改文字时 `w:id`、`w:hyperlink`、`relationship` 要对得上，否则 orphan。
- 页眉页脚：是**独立部件**（header1.xml / footer1.xml），改正文不会改页眉；首页页眉、奇偶页页眉可能不同，逐个查。
- 列表编号：改编号要看 `numbering.xml` 的 `abstractNum` / `num` / 段落的 `w:numPr`，用户「看到列表对了」≠ 底层编号对。

## 5. 域（TOC / 页码 / 引用 / 日期）

- TOC、页码、交叉引用、日期、邮件合并占位符**都是域**（`<w:fldSimple>` 或 `<w:instrText>`）。
- 改域源后，显示值是缓存的——必须让用户**更新域**（Word: 全选 Ctrl/⌘+A → F9）才会刷新，或你在生成的文档里标注「请更新域」。
- 别把一整个 `fldSimple` 当纯文本删掉，那会连域结构一起弄丢。

## 6. 保存前自查清单

1. `.docx` 依然是一个合法 zip，能被 unzip -t 通过。
2. 没有逻辑：删了可见文字却留下空段落符/空项目符号——删干净或清空属性。
3. 修订/批注没被我的「整段重写」误伤。
4. 表格用的是显式宽度（受控时），不是会被别家重解的百分比/auto。
5. 页眉页脚媒体关系的 id 对得上，图片没断。
6. 域（目录/页码/引用）让用户在打开后更新一次。
7. 已在心里过一遍「同一个文档拿到 Google Docs / LibreOffice 会不会脚」。
