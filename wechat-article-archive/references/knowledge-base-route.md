# 面向 AI 知识库的沉淀路线

## 面向 AI 知识库的沉淀路线（不只是做成读物）

如果目标是把文章喂给某个 AI 专家/知识库（而不是给人读的 HTML/Word），用这套：

脚本：`C:\Users\Lenovo\MediaCrawler\wechat_archive.py` + `wechat_index_select.py` + `wechat_sogou_search.py`
（解释器 `.venv\Scripts\python.exe`，产出落在知识库 `00-原始素材/公众号归档/`）

```bash
# ① 从 GitHub 索引库挑某个号的议题文章（无需任何凭证）
python wechat_index_select.py --account "真实故事计划" --strict --limit 20 --out urls.txt
python wechat_index_select.py --list        # 列出 246 个可归档的号
# ①b 索引库没收录的号（凤凰网系等）→ 搜狗微信文章搜索，按账号名正则过滤、按账号自动分文件
python wechat_sogou_search.py --query-file queries_phoenix_women.txt \
  --account-re "^(凤凰WEEKLY|凤凰网公益|凤凰网财经|凤凰网|脱氧核甜)" \
  --pages 2 --limit 110 --sleep 2.5 --split-dir phoenix_urls
# ② 归档 + 自动沉淀（含广告门禁）
python wechat_archive.py --file phoenix_urls/urls_凤凰WEEKLY.txt --account "凤凰WEEKLY" --sleep 2
# ③ 只调规则时用 raw.jsonl 离线重算，不重新联网（会重跑广告判定并重建台账）
python wechat_archive.py --rebuild --cycle 2026-09-20
```

产出：`articles/*.md`（frontmatter + 正文 + 核心论点 + 表达样本）、`insights.md`（议题分布/逐篇沉淀）、
`raw.jsonl`（留痕，也是 `--rebuild` 的依据）、`seen.json`（URL 去重）、
`ads-filtered.md`（广告过滤台账）。

> **下一步（把语料变成能力）见技能 `expert-corpus-ops`**：归档只解决"采到"，
> 要让知识库"能用"还得过提炼层（抽段落判断句而非小标题、合并软换行再切句、
> 按主题聚类后写成处境地图）。本技能只负责把语料正确地落到归档层。

### 这套路线的关键经验

- **GitHub 索引库是无需凭证的整站归档突破口**：`api.github.com` 列目录 +
  `cdn.jsdelivr.net/gh/sushengbuhuo/blog@master/docs/wechat/<文件名>` 下载（raw.githubusercontent 不通时走 jsDelivr）。
  文件是 `[日期_标题](链接)` 格式，实测一个号 369 条里能筛出 20 条议题相关。
- **老文章有相当比例取不到正文**（实测 20 篇挂 5 篇）。先诊断再下结论：看页面里是
  `js_content` 还是 `js_content_container`——**后者是微信新版页面/失效页**，页面标题为空、
  没有 `rich_media_content`、没有 `var nickname`，属真取不到，重试无用。
  还有一类是"该内容已被发布者删除"，多为推广软文到期下架，不是作者删的。
- **场景标签用词频打分，不要"关键词首次命中"**：长文杂词太多（心理学文章满是
  "心理工作/工作坊"，会把原生家庭文章判成"职场成长"）。标题权重 5 倍、正文权重 1；
  同时**去掉"工作"这类泛词**，补上"原生家庭/讨好型/自我攻击/依恋"等垂直词。
- **提炼噪声要显式过滤**：`图源 / 图虫 / pexels / 导语 / 课程 / 讲师 / 策划 / 监制 / 客服 /
  扫码 / 版权 / 点击 / 关注我们`，以及"人名+冒号"的对话行，否则观点框架里全是噪声。
  人物类图文稿还要补：`撰文 / 摄影 / 供图 / 受访者 / 视觉中国 / 出品 / 总监制 / 主持人 / 嘉宾`，
  以及**图注特征行**——以"现场/合影/照片/毕业照/资料图"收尾、或结尾带"（左一）"站位标注的行。
- **失败要记清原因**，别笼统报"抓取失败"，否则无法判断该不该重试。
- **标题里的 HTML 实体必须解码**：微信 `<h1 id="activity-name">` 里带 `&quot;` / `&amp;`，
  不解码会写进 frontmatter 和文件名（实测出现 `...家庭的&quot;难言之隐&quot;.md`）。
  `unescape()` 之后**还要给 YAML 双引号标量转义引号**，否则
  `title: "…的"难言之隐""` 直接把 frontmatter 写坏。
- **正文清洗要去图片行与关注引导语**：微信正文里满是 `[图片] https://mmbiz.qpic.cn/...`，
  以及"点击蓝字XX，星标★或置顶公众号"这类引导语，对知识库纯属噪声。
  去掉后要压连续空行，否则留下成片空白。
- **`--rebuild` 要跟得上规则升级**：它读的是 `raw.jsonl`，所以重算要显式重跑
  `clean_body + desensitize + 标题归一`，并在文件名/判定变化时**删掉旧文件**
  （否则改名后新旧两份都在，判为广告的还留在归档里）。重算完把归一化结果**回写 raw.jsonl**，
  状态才稳定、不会每次重算都漂移。
- **广告门禁的阈值必须按篇幅分档**：长文叙事天然带"购买/下单/安利"等日常词。
  实测 1.7 万字《一个单身女性的身体探索》（真实故事计划）因一句"躺在购物车里，点击购买"
  被一票否决误杀——那是主人公自述，不是带货。改成：**元标签一票否决，CTA 话术只计分
  （长文 +6 / 短文 +14），阈值长文 ad≥34/suspected≥22、短文 ad≥22/suspected≥12**。
  合成用例回归：元标签短文→ad、短带货→ad、长软文→ad、长文叙事→clean、正常媒体文→clean。

### 场景标签怎么判：三条都踩过

给归档文章打场景标签（情感关系/职场成长/健康身心/自我认知/穿搭审美/性别与社会）时，
下面三种写法都会出错，最后一行是能用的：

| 写法 | 症状（实测） |
|---|---|
| 先匹配先返回 | 命中一个词就定场景 → 泛词把什么都吸走 |
| **词频总和**打分 | 长文里同一个词重复 14 次就定主题（《中国中老年女性活得有多野》"骨质疏松"×14 → 健康身心） |
| 词频 + 低分也采纳 | 稀疏噪声定主题（《美国华人妈妈》仅 2 分也被判健康身心） |
| **✅ 标题命中即认定 + 正文比"命中不同关键词数"≥2** | 129 篇里「其他」仅 8 篇（6%），误判消失 |

配套两条词表纪律：
- **单字代词不得入表**（`他`/`她` 几乎每篇都有 → 全部语料被吸进一个场景）
- **单字不许入表**（`妆` 会子串命中"女装"）—— 一律用双字以上专有词；
  健康类尤其不能用 `健康/病/疼/药` 这类泛词（`疼` 会命中「心疼」）

### 主流媒体的来源该怎么定：优先拿公众号，不要退化成抓网站

**这是踩过的坑，务必先读。** 用户说"采集南方周末、凤凰网等主流媒体的文章"时，要的是**它们的微信公众号推文**，
不是媒体的自有网站。索引库（246 个号）**不含凤凰网系**，当时我图省事退化成抓 `gongyi.ifeng.com` 网站页面，
采了 34 篇——**来源错了**，用户直接指出"这个是凤凰网公众号，不要爬错成网站"。
网站编辑稿与公众号推文是两套口径，混在同一知识库里会导致检索重复、口径混乱。

**正确解法：索引库没有的号，用「搜狗微信文章搜索」定位真实推文。**

- 入口：`https://weixin.sogou.com/weixin?type=2&query=<词>`。**只用 `type=2`（文章搜索）**；
  `type=1`（公众号搜索）实测无结果，别浪费时间。
- 结果块 `<div class="txt-box">`；账号名在 `<span class="all-time-y2">`；链接是 `/link?url=...` 中转，
  需解析页面里的 `url += '...'` 片段拼接，才能还原成带 `signature` 的
  `mp.weixin.qq.com/s?src=11&timestamp=...&signature=...`。
- **⚠ 限流是硬约束，决定了整条通道的用法**：单会话累计约 **30~55 次请求后整站返回空**——
  搜索页直接 0 条、`/link` 解析全败，且**换会话 + 冷却 20 分钟都不恢复**（疑似按 IP 计）。
  实测：第一轮 54 成 / 56 败断崖式全败；第二轮跑到第 3 次搜索就 0 条；第三轮 1 页之后即封。
  应对：**每次只跑 2~3 个查询词、`--pages 1`、`--limit 25`**，被限流就当次收工、隔次再续采；
  脚本内置「连续 3 次搜索返回 0 条即提前结束」与「连续 4 次解析失败即冷却 120s 换会话」两道保护。
  **不要连环重试，不要换 IP/代理绕过。**
- **链接解析失败也要先落盘**：st 链接有时效，中途被限流会让已解析的成果白跑——脚本已改成
  每解析成功一条就 flush 一次输出文件。
- **查询词用「账号名 + 议题词」**（如 `凤凰WEEKLY 婚姻`），再按 `--account-re` 过滤账号名。
  直接拿账号名当查询词会搜出一堆招聘帖。
- **中转链接里的空格要转义**（`link.replace(" ", "%20")`），否则 `urllib` 报 `InvalidURL`。
- **这类 `src=11&timestamp&signature` 链接有时效**，当次必须归档完，不要隔天再抓。
- 噪声号（凤凰自行车 / 凤凰艺术 / 凤凰读书）用账号正则天然排除；不确定真实账号名就先 `--dry` 干跑看一遍。
- `--split-dir` 按账号名把结果自动拆成多份 URL 文件（归档脚本每次只认一个 `--account`，
  多账号混采时必须拆），文件名形如 `urls_凤凰WEEKLY.txt`。
- 已知可用的凤凰系账号：**凤凰WEEKLY**（主号，女性议题富矿，一跑就是 50+ 篇）、凤凰WEEKLY财经、
  凤凰网公益频道（她势界）、凤凰网（1/100 计划）、脱氧核甜。

**`--root media` 只留给"确实没有公众号"的媒体**（此路已停用：那批网站内容已隔离到 `00-原始素材/_已废弃_网站版/`）。
真要用时注意：

- **归档根按来源分目录**，`seen.json` 与 `index.md` 也要**按根隔离**（否则两个进程并发写同一份去重表会互相覆盖，
  表现为同篇文章被归档两次、索引里统计串号）。
- **主流媒体必须用双条件严格过滤**：标题须**同时**含「女性主体词（女性/她/妈妈/妻子/主妇…）」
  与「议题词（成长/职场/婚姻/家庭/性别/独处…）」。只按单关键词筛，南方周末这类综合媒体会
  筛出一堆"杀妻/落马/坠楼"社会新闻——那是新闻，不是女性成长议题。
- **非微信站点的正文提取**：先试容器候选（`main_content / articleContent / TRS_Editor / RichText` 等），
  取文本最长者；**不足 200 字时用「段落聚合」兜底**——把全文所有 `<p>` 且长度 ≥12 的去标签后拼接。
  凤凰网 `i.ifeng.com` 有 `main_content` 容器，但 `gongyi.ifeng.com` 用的是 **CSS-module 哈希类名**
  （`index_text_D0U1y`，每次构建都变），固定选择器必然落空，只有段落聚合能拿到正文。
- **图文型专题稿（如凤凰网「1/100 计划」）的提炼天然偏噪**，因为正文以图注为主；
  正文 `.md` 全文是完整的，观点框架只是辅助，别为追求提炼洁净而牺牲归档。
- **目录要惰性创建**：全部 URL 因去重被跳过时不要留下空目录，否则索引里会多出"0 篇"的周期目录。

### 公众号广告推文必须过滤（用户硬要求）

用户明确要求：公众号上的广告推文要**主动识别并过滤，且不纳入知识库沉淀**。
`wechat_archive.py` 已内置 `detect_ad(title, body)`，**元标签一票否决 + 计分两档**：

- **元标签一票否决 → 不归档、不沉淀**：`本文为广告 / 以下为广告 / 广告丨 / 推广丨 /
  品牌特约 / 特约发布 / 赞助内容 / 推广内容 / 商务合作请联系 / 广告合作`。
  这类出现在正文里几乎不可能是叙事的一部分。
- **CTA 话术只计分，不能一票否决**：`点击购买 / 立即购买 / 立即下单 / 扫码购买 / 领取优惠券 /
  到手价 / 直播间同款` 等——**长文（≥1200 字）只 +6，短文 +14**。原因见上文「阈值必须按篇幅分档」。
- **弱标记累计打分**：促销词频计数（每个词封顶 +3）+ 价格折扣正则
  `[¥￥]\d|立省\d|省\d+元|仅需\d|\d+折|满\d+减` (+6) + 联系方式正则
  `微信[:：]\S{4,}|加我微信|扫码进群` (+8)；**短文案（<1200 字）再加权 +6**。
- **阈值分档**：长文 `ad≥34 / suspected≥22`；短文 `ad≥22 / suspected≥12`。
  `ad` → 拦下不归档；`suspected` → **正文归档但排除沉淀**，待人工复核。
- 台账写同目录 `ads-filtered.md`，分「已拦截 / 疑似待复核」并列出命中词；**跑完必须核对**，
  确认是广告可直接删对应 md。
- `insights.md` 沉淀只收 `clean` 篇目；`--rebuild` 离线重算会重跑广告判定，
  并把新判为 `ad` 的**撤回归档**（删掉历史 md）。

**广告识别要在归档前做**（不是事后清洗）——否则广告正文会先污染 `articles/` 与提炼结果。
实测 8 个主流媒体账号（凤凰WEEKLY 52 / 真实故事计划 15 / 南方周末 12 / Vista看天下 12 /
新周刊 11 / 人物 5 / 财新 4 / 首席人物观 2）**全部 0 命中**：正规媒体自律较好，
加上门禁已修掉误伤，属正常结果——不要因为"一篇都没抓到"就怀疑门禁失效，
用上面那组合成用例回归验证即可。
