# 覆盖诊断、补词闭环与多轮迭代（rank-records）

### 覆盖诊断：缺词候选（默认开启）

上一条「覆盖靠人」是人力的瓶颈。本步骤**顺带**扫一遍题名，提取「重复出现且不在词表」的领域词，
在产物末尾输出一节「建议补词」+ **可直接粘贴的补词串** ⇒ 人只需挑词，不必通读全量。

```bash
node scripts/rank-records.cjs --dir DIR --topic "..." --near "..." \
  --suggest-scope near --min-df 2 --suggest-top 20     # 三者均为默认值，可省略
```

| 参数 | 说明 |
|---|---|
| `--suggest-scope` | **最低档位（单调包含）**：`near`（默认 ＝ 主题档 + 相邻档）／ `exact`（只扫主题档）／ `all` |
| `--min-df` | 至少出现在几条记录里才算「高频」（默认 2）。**只要某新术语出现 1 次就够时用 `--min-df 1`** |
| `--suggest-top` | 最多列几个候选（默认 20）；`--no-suggest` 彻底关闭（产物与旧版逐字节可比） |

**为什么默认是 `near`（而非只看主题档）**：最需要补词的场景恰恰是**主题档为空**，
而缺词证据留在**相邻档**（繁体猫 CKD 论文就落在 near 档）。只看主题档 ⇒ 功能在最需要时返回空。

**三条降噪判据（逐级更一般）**：等值 `研究` → 全拼接 `研究进展`（＝研究+进展）→
**窗口残渣** `究进`／`物犬`（词窗接缝处拼出的碎片）。第三条用**结构性判据**
（候选每个字都出现在通用词/物种词里），因为**逐词加黑名单会「按下去又弹起来」** ——
实测把 `宠物犬` 补进物种词表后，其尾巴 `物犬` 立刻冒出来（df=2）。

候选分三类，**一律不自动改词表**（只提示，由人勾选）：

| 类别 | 含义 | 处置 |
|---|---|---|
| `词表外` | 新领域词（如 `猫尿石症`） | 直接补进 `--topic` |
| `词表词+修饰` | 词表词的超串（如 `肾脏保健` ⊃ `肾脏`） | 高价值补词方向 |
| `半重叠·待人工` | 与词表词有 ≥2 字公共子串但互不包含 | 既可能是真缺词（`菌群失调`），也可能是 n-gram 分词错位（`脏保健复`）⇒ **只降权不丢弃** |

候选的 `term` 保留**原文形态**（`腎臟保健`／`乳酸桿菌`），`key` 才是归一形态 —— 与 `snippet` 策略一致。
补词串可直接粘贴：归一化会兜住繁简与连字符差异。

⚠️ **已知边界（如实登记）**：本模块回答的是「**哪些高频领域词缺失**」，**不是**「某一条记录里有什么新词」。
`--min-df 1` 时候选会混入大量单次出现的错位片段（df=1 排在末位）。后者仍要人工看那条记录的题名
（即「形态靠代码、**覆盖靠人**」这条底线不变，本模块只是把人力从「通读全量」降到「挑词」）。

### 补词闭环：勾选后重排 + 效果对比（`--apply`）

上一条给出候选清单，但「补进去到底有没有用」仍需手工再跑一次。本步骤把这段接成闭环：
**显式勾选**候选词 ⇒ 并入主题词表 ⇒ **原地重排**（只读同一批 `raw/*.json`，站点无需重跑）⇒
输出「补词前 → 补词后」对比小节。

```bash
node scripts/rank-records.cjs --dir DIR --topic "..." --near "..." \
  --apply "肾脏保健,乳酸杆菌,肠道保健" --out DIR/ranked-applied
```

| 行为 | 说明 |
|---|---|
| 主视图 | 变为**补词后**的结果；对比小节内嵌在报告头部（表格之前） |
| 对比内容 | 主题命中数 / 命中率 / 相邻·跑题数变化 · **升级清单**（含「新增命中词」＝是哪个补词起了作用）· 降级清单 · **词表 v2**（完整串，可直接替换 `--topic` 原值） |
| 站点请求 | 仍为 **0**（重排纯本地；报告头部会显式声明） |
| 不自动改词表 | `--apply` 是**唯一**入口；不加该参数则主题词一律不变 |
| 勾选词已全在词表中 | **显式报错**（否则用户会误以为补词生效 —— 静默空操作必须避免） |

**★ 不变量**：补词只会增加命中 ⇒ 分数单调不减 ⇒ **降级必为 0**。
对比小节若报出降级，即为缺陷信号，须人工核查（而非当作正常波动）。

**★ 保原文形态**：词表 v2 里的 `SCFA` 就是你输入的写法（本步骤只 trim，不做形态归一）。
而报告头部「主题词」与表格命中列显示的是**归一后**形态（`scfa`）—— 那是**匹配用**的表示，
不代表词表被改写。两者分工不同，勿混读。

**闭环的实际价值**（gutkidney 实测 40 条）：补入 `肾脏保健,乳酸杆菌,肠道保健` 后，
繁体猫 CKD 学位论文由「相邻主题 rank 16 / 分 4.5」升到「**主题命中 rank 2 / 分 13.5**」，
主题命中率 35% → 37.5%，降级 0 —— 这就是「补词有没有用」的**量化答案**。

### 多轮迭代：回答「这个词表还能挖到多少」（`--iterate`）

单轮 `--apply` 答的是「补这几个词有没有用」；`--iterate` 答的是**上限**：
把「诊断 → 补词 → 重排」迭代到收敛，给出每轮增益曲线、饱和轮次、以及**收敛后仍不命中的记录**。

```bash
node scripts/rank-records.cjs --dir DIR --topic "..." --near "..." \
  --iterate 8 --iterate-batch 5 --iterate-pick all --out DIR/ranked-iterate
```

| 参数 | 说明 |
|---|---|
| `--iterate` | 轮数 1–8（默认关闭）。跑到「无候选 / 无增益 / 达上限」即停 |
| `--iterate-batch` | 每轮补入上限 1–50（默认 5）—— 模拟「一次挑 K 个」而非一次全取 |
| `--iterate-pick` | `all`（默认，全取候选 = 上限探测）｜`extends`（只补「词表词+修饰」，半重叠类进 deferred） |

**与 `--apply` 互斥**（同时给会报错）：`--iterate` 是**探测**（自动取词，不代表建议词表），
`--apply` 是**采纳**（人工勾选）。正确顺序：先 `--iterate` 看上限 → 再从候选中人工挑 → `--apply` 落地。

**★ 三档分工（没有「既不漏真词、又不进残渣」的自动档 —— 这是本技能的诚实结论）**：

| 档 | 自动补什么 | 得到什么 | 可信度 |
|---|---|---|---|
| `--iterate-pick all` | 全部高频候选（含 n-gram 错位片段） | **词表覆盖率上限**（天花板） | 数字可信，词不可信 |
| `--iterate-pick extends` | 只补「词表词的延伸」（`肾脏保健` ⊃ `肾脏`） | **安全增益**（语义上只是把已知词延长） | 词可用，但常常为 0 |
| `--apply` | 人工挑的词 | **可采纳的词表 v2** | 唯一可信通道 |

**★ 读数的硬边界（最容易误读的一点）**：`all` 档的命中率是**「词表覆盖率」而不是「主题相关性」**。
因为候选本身来自题名 ⇒ 补进去必然命中 ⇒ 数字必然接近 100%，但这只证明**字面覆盖**。
gutkidney 实测：35% → **95%（6 轮饱和，补 25 词）**，其中 `慢性肾`／`性肾衰竭`／`道菌群代`／`犬血`
都是**分词错位片段** —— 覆盖率涨了，主题相关性没涨。**要论主题相关性，只能靠 `--apply` 人工挑。**

**★ `residual`（收敛后仍非主题命中的记录）才是真正有用的产物**：
它把「补词治不了」的记录单列出来 —— 这些不是词表写法问题，而是**缺主题维度**。
gutkidney 实测 2 条，其中《猫慢性膀胱炎合并肾炎病例的诊治》属「猫泌尿 + 肾脏」临床维度
（与「肠-肾轴 × 菌群」不同轴）⇒ 须新增主题维度，而非继续补词。

**★ 维度诊断：残差「缺的是哪个维度」（`--iterate` 报告内自动附一节，JSON 同挂 `iterate.diagnosis`）**：
`residual` 只给清单，逐条通读仍费人。诊断把残差按**共现指纹**聚成维度候选：

| 簇类型 | 判定 | 处置 |
|---|---|---|
| `new-dimension` | 簇内术语与主题词表/相邻词**零 ≥2 字重叠** | 疑似缺一个主题维度 ⇒ **人工确认后**再决定加词或改检索式 |
| `axis-extend` | 与现有轴有 ≥2 字重叠 | 同一轴上的写法差异 ⇒ 用 `--apply` 补词即可，**不必**新增维度 |

成簇三道闸（缺一不可）：① 簇内 ≥2 条记录（个案不是维度）；② 簇内**至少 2 个共享指纹**
（只有 1 个共享词的簇多是泛学术词拼成的 —— 实测 `生物` = 合成生物学／生物安全／生物风险、
`肠道` = 肠道寄生虫／肠道菌群，判 `no-cohesion` 剪除）；③ 种子按**新维度优先**认领
（否则轴内高频词会把含新维度词的记录一并吞掉，新维度整簇消失）。
一条记录只归一个簇 ⇒ `support` 之和 ≤ 残差数（数字可对账）；被剪记录逐条列出并标原因
（`no-shared-term` / `spun-off` / `no-cohesion`），不静默丢弃。

**只提示，不自动建**：提案 `proposal.keywords` 永不回流词表，`autoApply` 恒 `false`；
采纳唯一通道仍是 `--apply`（或据此改 `--keywords` 重跑检索）。`verdict` 四态：
`no-residual` / `no-shared-terms` / `axis-only` / `new-dimension`。

实测（2026-10-18 · 站点零请求）：gutkidney 全词表下 2 条残差互不相关 ⇒ 判 `no-shared-terms`（不硬凑）；
猫毛球 10 条全 off ⇒ 同为 `no-shared-terms`（真实病因是**检索式召回过宽**，不是缺词）；
词表收窄到 5 个中文词后 ⇒ 聚出 `Kidney` 簇（5 条强证据，术语 `Kidney`／`Chronic Kidney`／`Axis`），
正确指认「英文 kidney 轴缺失」。**稀疏维度（仅 1–2 篇）按设计识别不出来** —— 个案不是维度。

**★ 建议检索式：诊断 → 处方（`--iterate` 报告内自动附一节，JSON 同挂 `iterate.diagnosis.queries`）**：
诊断只答「缺哪个维度」，人还得自己想「拿什么式子去验证它」。该层把**新维度簇**直接翻成可粘贴的检索式。

```bash
node rank-records.cjs --dir DIR --topic "…" --iterate 2 --species auto --query-cap 4
```

| 参数 | 作用 |
|---|---|
| `--species auto` | 默认。按题名探测 `cat` / `dog` / `both`（都出现或都不出现 ⇒ `both`，**宁宽勿窄**：漏物种块会大幅降召回） |
| `--species both\|cat\|dog\|none` | 显式指定物种块。**只改建议式，不改排序结果** |
| `--query-cap N` | 每条式的术语上限 1–8（默认 4），超出者进 `dropped` 并告警 |

- **只出方案、不执行**：`executed` 恒 `false`、`stationRequests` 恒 0；每条式 `verified: false`（未实测）。
  检索是有成本的动作，「值不值得照这个方向再搜一轮」是人的判断。
- **中英分条**：中文术语配中文物种块、英文术语配英文物种块 —— 站点是中英双语库，一条式盖不住两侧索引。
- **语法只走白名单**（`AND` / `OR` / 括号 / 自由词）。多词短语**不加引号**（引号语法实测返回 0 条）⇒
  按「各词均出现」匹配、**召回偏宽**；每条式自带该告警，实测后须按命中上下文收窄。
- **★ 主题锚（v2）**：式子结构是 `物种 AND 维度 AND 主题锚`，不是 `物种 AND 维度`。
  锚取自**词表**里同语言的词（按原序取前 2 个，跳过与维度术语互为子串者；单字锚不用）。
  理由是一手实测：无锚式 `(cat OR feline) AND (Kidney OR Kidney Disease OR Chronic Kidney OR Axis)`
  真跑取回 16 条猫 CKD，而全词表下 15 条只到 `near`（有 kidney、无任何肠侧词）——
  式子把主题丢了，取回的是「猫肾病」整个大类。**该语言下没有可用锚时，式子照出但必带告警**
  （`anchorSource: 'none'`），照用时须逐条核读。
- **术语去冗余**：是另一术语真子串、且不是簇标签者剔除 —— OR 里加子串只会放宽召回、不增加定向性。
  实测：`Chronic` 被剔（`Chronic Kidney` 的子串）、`Kidney`（簇标签，虽也是子串）保留。
- **物种粘连必剪**：`Canine chronic` → `chronic`、`猫膀胱炎` → `膀胱炎`、`猫膳` → 半词（`膳` ⊂ `膳食纤维`）。
  不剪则式内会出现「物种块 AND `Canine chronic`」这种自相矛盾的组合。
- **同轴簇不出方案**（进 `skipped`）：补词比换式子便宜。

实测（2026-10-18 · 站点零请求）：gutkidney 全词表 ⇒ 1 条英文式
`(dog OR cat OR canine OR feline OR companion animal OR pet) AND (Kidney OR Kidney Disease OR Chronic Kidney OR Axis)`；
猫毛球 10 条全 off ⇒ **0 条**（`no-shared-terms` 时不臆造）；窄词表 ⇒ 1 条英文式 + 1 个同轴簇进 `skipped`。

**★ 跨运行收敛记忆（`--converge-state [文件]`，需与 `--iterate` 同用；只报一次）**：
收敛判据只活在单次运行内 ⇒ 同一个 `stalled` 维度会每份报告重报一遍、式子也重给一遍。
带同一状态文件重复运行，每份报告就知道「这个维度上次报过、结论有没有变」。

```bash
node rank-records.cjs --dir DIR --topic "…" --iterate 3 --converge-state
```

**省略路径** ⇒ 落点 `DIR/converge-state.json`（记忆跟着语料走，不必每次手带）。

| 跨运行 `trend` | 判据 | 处置 |
|---|---|---|
| `new` | 历史无此维度 | 首次给出式子 |
| `persistent` | 上次活着、本次还活着 | 报过 ≥2 次且 `stalled` ⇒ **不再出式子** |
| `resolved` | 上次活着、本次末轮缺席（本次出现过） | 无需处理 |
| `cleared` | 上次活着、本次连出现都没有 | 无需处理 |
| `recurred` | 上次**已判收敛**、本次末轮仍在 | **重报**：上次的收敛不可信 |

- **★ 一个文件装多个主题（`slots[]`）**：每个 `--topic` 一个槽。换词表 ⇒ 本主题无槽 ⇒ **按首次处理**，
  其他槽**原样保留**。v1 单主题文件自动迁移（数据零丢失）。
  双键匹配 = `hash` + `topic` —— 只看 hash 有碰撞风险，只看 topic 认不出「同一主题换了写法」。
  词序变化不算换主题（规范化时排序）；语料规模变化**只告警**（`corpusChanged`）。
- **槽数上限 20**，超出淘汰最旧槽并在报告里点名（`evicted`）—— 丢记忆必须可见，不许静默。
- **抑制三条腿缺一不可**：`persistent` + `stalled` + 报过 ≥2 次。结论变了、刚回归、第一次都给式子；
  抑制必须显式记入 `suppressed` 并点名。
- **★ 抑制也标在「残差维度诊断表」上**：被抑制的维度**仍列在表里**（它确实是本轮残差，记录与命中上下文都在），
  但行内标「已报过 N 次 · 抑制」，小节开头点名计数（`已抑制 K 个维度（…）`）；逐簇判定，同表内「首次」与「已报过」必须能共存。
  提案段的候选词**不按抑制剔除** —— 本档只做标注，删不删由人判断。
  未传 `--converge-state` 时诊断表**不加这一列**（旧报告形状零变化）；JSON 通道给 `diagnosis.crossActive`
  + 每簇 `trend / reportCount / suppress`（`crossActive=false` ⇒ 三者恒为 null / 0 / false，**不得当「首次」读**）。
- **★ 回归看「末态」不看「出现过」**：本次 status 也是 `resolved`（出现过又被消掉）是**持续收敛**，不是回归。
- 状态文件在**报告全部落盘之后**才写（反之会让下一轮静默抑制）；序列化恒定（key 升序 / 秒级 UTC / LF）可逐字节 diff。

实测（真实语料 48 条 · 站点 0 请求 · 连跑 3 次）：第 1 次 3 个维度全部 `new` 并各给 1 条式；
第 2 次 `Kidney` `persistent`（报过 2）⇒ 抑制、`调控`/`慢性` `cleared` ⇒ **式子 0 条**并显式注明「已抑制 1 个维度」；
换词表再跑 ⇒ 本主题无槽、按首次处理并重新给式子，**且原主题的槽原样保留**（v1 时代这一步会把 3 次历史清成 `runs=1`，实测于 `fix4-changed`）。

**停止原因四种（穷举，不会出现「说不清的停止」）**：`no-candidates`（无语料内可补词）·
`no-gain`（补入未增主题命中，不空转）· `max-rounds`（达上限）· `all-covered`（防御性：
候选全部已在词表 —— 跨模块去重语义一致性的防线）。
