## [v4.15] — 2026-10-26 — 多源层内核 + 全文六级回退链（含 PDF 抽取）：让一条渠道挂掉不再等于整次失败

**为什么发这一版**：`[未发布]` 累积 4 条，三条动因都出在**单点**上，而且都是「挂了看不出来」这一类。① 站点通道：4 条检索式里 3 条 `collect_failed`，工具只在「全 0 且无读数」时报错 ⇒ **部分失败完全静默**，使用者会以为「这条检索式真的没结果」并据此排除一个有效方向。② 全文通道：只有 `enrich.pmcid → EPMC XML` 一条路，15 篇里 6 篇有 DOI 无 PMCID ⇒ 连尝试机会都没有（6/15）。③ PDF：Unpaywall 给出 11 个 PDF 直链，实测只有 1 个真能下载——而「给得出链接」被当成「拿得到全文」，这是同一类错误的第三次出现。

本版把这三处都改成**多路 + 每路留痕**，并且**不牺牲诚实性**：拿不到就报原因，下不动的 PDF 只登记地址、不计入「已获取」；上一版把一篇只有站点样板的页面判成全文（227 词里正文 0 词），本版加了**真假判据**把它修成真全文。全文可得率的正确账是 **6/15 → 9/15**，其中含一处**自我更正**：上一版宣称的 9/15 里 1 篇是假阳性，故诚实基线是 8/15。

### 一、多源层内核（v4.15 / A 批）：源注册表 + 调度器 + 连接器契约

**动因（一手实测）**：同一批 4 条猫毛球检索式，kuluer 站点 3 条 `collect_failed`（`page.goto` 30s 超时），
而整次运行只在「全 0 且无读数」时报警 ⇒ 部分失败完全静默，使用者可能据此**误排除一条本来有效的检索式**。

- 新增 6 个模块（全 LF、零第三方依赖）：`lib/sources/` 下的 normalize / http / europepmc / crossref / index 五个连接器模块，外加 `lib/scheduler.cjs`。
  连接器契约 7 项必填，其中两项是踩过坑才懂的：`queryDialect`（认不认布尔式）与 `countSemantics`（命中数能不能进 PRISMA）。
- 三源实测契约：Europe PMC **直吃布尔式**且 `hitCount` 精确（可进 PRISMA）｜Crossref **完全不解析布尔**
  （布尔式与词袋的 total 与 top4 **逐字相同**）⇒ 必须转译，且其 `total-results` 是**全库软匹配规模**（775136 / 358659），
  **禁止当计数**｜OpenAlex 的 `mailto` **不提升限额**（官方提示原文），免费额度是 IP 级共享日预算，实测连续两次即 429 ⇒ 暂不接入。
- 调度器三条判据：**计数语义分流**（`none` 型源走 `not_applicable`；照搬三态会判成假故障并污染 `siteDegraded`）／
  **失败隔离**（单源抛异常或超时只记一条告警）／**跨源去重**（DOI 优先；无 DOI 按「规范化标题 + 年份 ±1」；
  `fibre`/`fiber` 用**英式-美式白名单**折叠，**不做**通用 our→or 折叠——误合并两篇不同文献比漏合并严重）。
- 自查修掉 4 个真缺陷（均已变异自证）：① `runOne` 写成 `Math.max(5000, perSourceTimeoutMs)`，把用户给的 800ms
  **静默抬到 5s** ⇒ 超时永不触发、「全源皆挂」被误判为正常；② 无 DOI 跨源合并被拼写差异打穿；
  ③ Crossref 的 775136 差点进 PRISMA；④ 变异脚本用 `Path.read_text/write_text` 把纯 LF 的 `scheduler.cjs` 整文件改成 CRLF。
- 闸门 459 → 500（+41），变异 9/9 命中目标断言。
- 价值实测：同 4 条检索式，多源 **4/4 有可信读数**（EPMC 合计 559 命中），原状 3/4 `collect_failed`；
  其中 Q1 时 Crossref 当场 429 而 EPMC 照常返回 ⇒ **降级真实生效**（不是纸面设计）。

### 二、CLI 接线（v4.15 / A-2）：`--sources` 多源通道 + PRISMA 各源读数

- 新增 `lib/multi-run.cjs`（聚合层，纯函数、零 IO）：把「每源读数」整理成主脚本既有的
  `keyword` / `records` / `aborted` / `diagnostics` 四个字段的形状 ⇒ qc / enrich / fulltext / dedupe / evidence / raw / PRISMA **零改动**即可消费。
  判据下沉到这一层的理由：计数能不能相加、0 条算不算失败，是**判据问题**；留在主脚本里就只能靠真跑网络验证。
- 新增参数：`--sources`（`all` / `http` / `id,id` / `all,-id`）、`--mailto`、`--source-timeout`、`--source-concurrency`，
  全部在**输入层**校验（未知源报错、`kuluer` 给「尚未迁入」专属改法、与 `--site` 互斥、`--mailto` 格式错必须报错——
  错格式会被 Crossref 静默忽略）。`--fulltext` 对 `--enrich` 的硬依赖在 `--sources` 下**放宽**（多源通道的 EPMC 连接器自带 pmcid）。
- **通道分流**：给 `--sources` 即**不启动浏览器**；playwright 改**惰性**加载（旧写法在模块顶层 require、缺依赖时 `exit(1)`，
  等于把无 Edge/Chrome 的 CI 环境挡在门外）；收尾 `if (browser)` 判空。不给 `--sources` 时行为与 v4.14 **逐字一致**。
- PRISMA 新增 **2.1 各源读数**（按源汇总 + 逐检索式明细 + **实际发出的转译检索式**）；章节号刻意用 `2.1` 而非插入新的一节，
  因为 3/4/5 节编号被报告正文与历史产物大量引用，重排会让交叉引用集体失效。
- 三条新判据：`not_applicable`（本次没有可计数的源）**不当故障**、**不计入** `siteDegraded`、**不算**「计数已知」
  （第三条是关键：否则「只跑 Crossref」会在报告里写出「合计 0 条」的假读数）。`fmtCount` 为它新增「不适用」字样。
- 自查修掉 2 个真缺陷（均由 e2e 抓到，单测首版漏了）：① 连接器的 `idx` 是**源内排名**，合并后出现 `1..5,1..5` 重复序号
  ⇒ 改为全局连续编号，源内排名保留在 `provenance.rank`；② 探针模式事件流写「取得 N 条」而 summary 是 0 条，自相矛盾
  ⇒ 改「源返回 N 条（探针模式未保留记录）」。
- 闸门 500 → 521；变异 **15/15** 命中。其中首轮 1 条 MISS、1 条 WRONG-TARGET 都属**用例夹具缺前提**
  （idx 夹具没带 `idx`；计数变异选错了靶），已修夹具与变异本身——不是放宽断言。
- e2e 三场景（真实网络）：双源 `exit 0`（10 条，PRISMA 2.1 双行、总耗时 ~3s）｜仅 Crossref `exit 0`
  （`not_applicable`，**不误判失败**）｜`--limit 0` 双源探针（141 / 69，全部 `counted`）。

### 三、全文四级回退链（v4.15 / B 批）：6/15 → 9/15（★ 其中 1 篇后被 C 批复核为假阳性，真实基线是 8/15）

**动因（一手实测）**：v4.14 的全文通道只有**一条路** —— 拿 `enrich.pmcid` 打
`EPMC/〔pmcid〕/fullTextXML`。同一批 15 篇实测只成功 6 篇，两个原因都在一处：
6 篇只有 DOI 没有 pmcid，**连入口都进不了**（`noPmcid` 静默跳过）；另 3 篇 `fullTextXML` 返回 500（不在 OA 全文子集）。
换句话说，失败不是因为「没有全文」，而是因为「只有一条路」。

- 新增 `lib/fulltext-chain.cjs`（914 行，零第三方依赖）。四级顺序与理由：
  **T1** `EPMC/〔PMCID〕/fullTextXML`（唯一有**章节结构**、能精确定位方法学节的通道）
  → **T2** `pmc.ncbi.nlm.nih.gov/articles/〔PMCID〕/` 正文 HTML（实测 3 篇只有这条路）
  → **T3** Unpaywall 定位 OA 版本（覆盖「不在 PMC 但在出版商免费」的 bronze/gold/green）
  → **T4** `doi.org` 后的出版商页（浏览器）。
- **入口解耦**：从「只认 `enrich.pmcid`」改为 `pmcid` / `doi` 双入口，且都做「enrich 优先、顶层兜底」。
- **两阶段调度**：Phase A 纯 HTTP 跑完全部目标；只有仍有失败且计划里尚存浏览器级时，
  Phase B 才启动**一次**浏览器统一处理 ⇒ HTTP 能拿到时完全不碰浏览器（A-2 的承诺得以保持）。
- 三条硬判据（每条都对应一个真实坑）：
  1. **抓到内容 ≠ 抓到该文内容**。挑战页/导航页/相关文章列表动辄数千词，只看字数会全判成功。
     每级都过「标题实词命中」闸门（≥2 个且 ≥40%）；标题缺失时**不做**归属校验，
     改为要求 ≥800 词并显式登记 `titleCheck: unavailable` —— 不假装验过。
  2. **有链接 ≠ 下得下来**。Unpaywall 对同一批给出 9 个 PDF 链接，实测只有 1 个真的返回 `%PDF`
     （Wiley/Elsevier/MDPI 全 403，Sage 连接失败）⇒ PDF 只登记地址，**不计入已获取全文**。
  3. **占位邮箱会被拒**。Unpaywall 对 `example.com` 返回 **422**（`Please use your own email address`），
     不是空结果 —— 若不与「真的没有 OA」区分，T3 会静默失效且看起来像端点挂了。
- 参数：`--fulltext`（语义升级为四级链）、`--fulltext-browser`（浏览器兜底，**默认关**）。
- 自查修掉 6 个真缺陷（均由变异自证或真实回归抓到）：
  ① `entryOf` 的 `doi` 只写了 `pick(e.doi)`，漏掉顶层兜底 ⇒ 多源记录计划恒为空，
    原缺陷「只有 DOI 进不了全文」被原样搬进新代码；
  ② `extractMainHtml` 用「HTML 字节数 >400」判断容器有料 ⇒ B2（1960 年老文章）抽到只有 21 字符正文的骨架就停，
     改为按**正文词数**判断；
  ③ `assessText` 只在调用方做挑战页检测 ⇒ 单测里 808 词的合成挑战页被判成功，改为闸门内部也查（用强特征）；
  ④ 失败原因取「最后一条 attempt」⇒ 6 篇真实原因（`no_oa`/`blocked`）被写成 `browser_disabled`（误导性诊断），
     改为取最后一个**实质尝试**；
  ⑤ 老式 PMC 页面（`/pmc/articles/<数字>`）容器套不上，落到 `whole_document` 把 `.gov` 样板混进正文
     （一篇 1939 年文章 226 词里约 80 词是导航）⇒ 加整行精确匹配的 `stripBoilerplate`；
  ⑥ T3 已判 `no_oa` 时仍去试 T4 ⇒ 对 4 篇 closed 各白跑 45s 浏览器超时换 0 条，改为跳过。
- 闸门 521 → **546**；变异 **10/10** 命中目标断言。其中 M9 首轮 **MISS**，查出原因是**我自己写的假断言**
  （用了 `captcha`，而它根本不在 `CHALLENGE_PATTERNS` 里 ⇒ 无论怎么变异都恒真），已换成确实在列表里的模式。
- e2e（真实网络，`--sources all --fulltext`，16 条）：**7 条拿到全文**，T1:4 / T2:1 / **T3:2**（Unpaywall 首次真实命中）；
  PRISMA 汇总出现按级分布行，方法学信号标注来源层级（XML 有章节结构 / HTML 无）。

**如实登记**：B 批原定验收判据「≥11/15」**未达成**，真实上限是 **9/15**。6 篇的确切不可达原因：
A1/A7/A8/C4 = `is_oa=false,status=closed`（Unpaywall 判定无任何 OA 版本）；A5/A6 = `probe_http_403`
（有 OA 位置但 Wiley/Elsevier 的 Cloudflare 拦截，headless 与 headed 实测都过不去）。
故判据校正为「**6/15 → 9/15（+50%）且逐篇可解释**」。

### 四、全文 PDF 抽取（v4.15 / C 批）：8/15 → 9/15，并修掉一个假阳性

**动因（先取证，结果把上一批的宣称证伪了）**：B 批收尾时我判断「PDF 文本抽取是唯一还有增益的一步」。
本批动手前先测 11 个 Unpaywall PDF 直链 —— **只有 1 个真回 `%PDF`**（A3 Cambridge），而 A3 早已被 T1 XML 覆盖，
**计数增益为 0**。Wiley 的 403 换 4 组请求头变体仍然全 403；PMC 的 `/pdf/` 路由返回的不是 PDF，
而是 PoW 挑战页（`POW_DIFFICULTY=4`，cookie `cloudpmc-viewer-pow`）。

但顺着这条线查出了**上一批交付的真缺陷**：B2（1960 年 Can Vet J）被判定为 `ok`，
1373 B / 227 词里**正文 0 词**，全是 `.gov` 站点样板与引用行 —— 一个会污染下游证据提取的**假阳性**。
即上一批上报的 9/15 里有 1 篇是虚的，**真实基线应是 8/15**。

于是本批真正交付三件事：

- **样板页闸门 `page_is_chrome`**（HTML 级）。判据取自真实样本对照，不是猜的：
  样板页（B2）散文行占比 0.04、散文行均词 13.3；成功样本 0.11–0.82、40–70。
  故「词数 <400 且散文行（≥8 词的行）占比 <10%」判为样板。取「且」不取「或」，
  避免短评述/勘误这类合法短文被误杀 —— 宁可漏，不可误。
- **零依赖 PDF 抽取 `lib/pdf-extract.cjs`**（只用内置 `zlib`）：暴力扫 `stream…endstream` + inflate，
  解 `(...)` 字面串与 `<...>` 十六进制串，按 `Tm`/`Td`/`TD`/`T*` 的 y 位移产生换行。
  **五类明确拒绝**：加密 / 无文字层 / CID 无 ToUnicode（hexRatio >30%）/ 控制字符超标（>20%）/
  **词间距丢失**（字母 >500 且空格比 <0.05）。任一条命中就报原因，不产半截乱码。
- **T2b：PMC PDF 级**（浏览器）。PMC 的 PDF 路由带 PoW 人机校验，本模块**不手写求解器**去绕过——
  那属于规避访问控制。做法是让页面自己的 JS 解：先开文章页建立同源上下文 → 开 pdf 路由触发 PoW →
  回文章页执行同源 `fetch`（实测只有这条路径能带上正确的请求头，直接换 cookie 走 API 仍 403）。

**实测（15 篇猫毛球，真实网络）**

| 条件 | 可得率 | 说明 |
|---|---|---|
| 不开 `--fulltext-browser` | **8/15** | B2 被样板闸门判 `page_is_chrome_148w_4pct_prose`，**诚实失败而非谎报** |
| 开 `--fulltext-browser` | **9/15** | B2 走 T2b 拿到 PDF，抽出 265 词真正文（`TRICHOBEZOAR OR HAIR BALL IN A CAT` / `A neutered male cat, 9years old.`） |

按级：`T1:5 T2:3 T2b:1`；好样本 C1/B1/D1 分别 1548 / 3645 / 3220 词，**未被样板闸门误伤**。

**两条实现教训（都是实测打出来的，不是设计出来的）**

1. **A3 的召回被当真值量过**：以该篇 T1 XML 全文为真值，PDF 抽取召回 **95.4%**（810/849 唯一词），
   标题实词 4/4 命中 —— 所以「零依赖抽取可用」这句话是有分母的，不是感觉。
2. ★ **PMC 的 OCR 文字层不写空格字符**：它用 `Td` 定位每个单词（`0.00 0 Td` / `33.36 0 Td` / `88.44 0 Td`）。
   初版只处理 `TJ` 数组里的字间调距，结果整页粘成 `TRICHOBEZOARORHAIRBALLINACAT`，只剩 66 词。
   补「`Td` 水平位移 >0.6 em ⇒ 空格」后变成 265 词；阈值取 0.6 em 是为了**不把逐字定位的 PDF 拆成单个字母**
   （0.1 em 的变异实测会把 `fibre` 拆成 `fibr e r`）。

**闸门与变异**：546 → **565** 项（+19：PDF 抽取 13 条 · 样板闸门 2 条 · 计划与层级 3 条 · 报告层展示名 1 条）。
变异 **12/12 命中目标断言**，0 MISS、0 WRONG-TARGET，sha256 全部还原。

**未做**：不升版（`TOOL_VERSION` 仍 v4.14）、不打包、不动资料库。PDF 文本抽取只接在全文链上。

> ⚠ **本段原有一句判断错误，F 批已更正**：原文写「`--sources` 通道不开浏览器 ⇒ 走不到 T2b，这是有意为之」。
> 真相是「**默认关**」而非「硬禁止」—— 两套浏览器互不影响：检索层的 `exe`/`browser` 按 `useMulti` 分流，
> 全文层走的是 `fulltext-chain` 自己的 `openBrowser()`。显式给 `--fulltext-browser` 时多源通道**能**走到 T2b
> （2026-10-26 实测 `byTier` 记 `T2b_pmc_pdf: 1` / 72998 B）。详见「五、F 批」。

### 五、多源通道 × 全文层浏览器开关（v4.15 / F 批）：把「默认关」与「硬禁止」区分开

**动因**：C 批收尾时我写下「`--sources` 通道不开浏览器 ⇒ 走不到 T2b，这是有意为之」。这句话是**错的**，
而且我在建议下一步时把它当成事实，提出「F 批需要你先决定这条承诺是否让步」。动手第一件事是实测，
结果推翻了前提。

**双向实测（2026-10-26，真实网络）**：

| 命令 | 结果 |
|---|---|
| `--sources europepmc --keywords "PMCID:PMC1585353" --fulltext --fulltext-browser` | `ok 1` / `byTier` 记 `T2b_pmc_pdf: 1` / `bytes 72998` / `browserUsed true` |
| 同上，**去掉** `--fulltext-browser` | `ok 0` / `failed 1` / `byStatus` 记 `page_is_chrome_148w_4pct_prose: 1` / `browserUsed false` |

结论：多源通道**本来就能**走到 T2b，只是默认不开；不开时不是「静默少一篇」，而是如实判 `page_is_chrome` 失败。
原句把「默认关」写成了「一律不启」，属表述错误，不是功能缺失。**代码一行未改。**

**根因：两套浏览器，互不影响**

| 层 | 谁在用 | 开关 | 多源通道行为 |
|---|---|---|---|

### 二、状态文件原子写（2026-10-24，批 1/4）：消除「并发读者读到半截 ⇒ 判 CORRUPT ⇒ 清空全部槽」

- **真正的风险不是「最后写者赢」，而是整份记忆被清空**：`rank-records` 的读在 run 开始时（1002-1011）、写在报告落盘之后（1065-1069），
  中间隔着整次运行；而 `readPrior` 把「解析失败」判为 `CORRUPT` 并**覆盖写回**。一旦并发读者撞上 `writeFileSync` 的截断窗口，
  20 个主题槽就一次性消失 —— 一次偶发并发被放大成全量数据丢失。
- **实测（`prove-m2.cjs`，624,615 B / 20 槽 × 200 维度，写 200 次）**：

  | 写法 | 读到空文件 | `JSON.parse` 失败 | 读到合法内容 |
  |---|---|---|---|
  | `writeFileSync` | **128** | **67** | 12 |
  | 原子写 | **0** | **0** | 1870 |

- **修法**：新增 `scripts/lib/atomic-write.cjs` —— 同目录唯一临时名（pid + 12 位随机）→ `openSync('wx')` → `writeSync` 循环 →
  `fsyncSync` → **rename** 覆盖。临时名必须与目标**同目录**：跨文件系统 rename 会退化为 copy，原子性直接消失（闸门有用例钉住）。
  `rank-records` 的状态写入改走 `AW.writeAtomicSync`，父目录自建由模块负责（调用点不再重复做）。
- **★ Windows 专有陷阱（实证；不处理会让修复在并发下反而写失败）**：`rename` 覆盖一个**正被其他进程打开**的文件时，
  Windows 抛 `EPERM`（POSIX 允许，Windows 不允许）。首版无重试，同一装置实测 `wrote: 1` —— **第一次就被 reader 的读句柄挡住**，
  原子写完全没生效。但并发读者的句柄是瞬时的（`readFileSync` 打开即关）⇒ 正解是**退避重试**
  （`EPERM`/`EBUSY`/`EACCES`，12 次 × 8 ms 递增、约 620 ms 封顶），**不是放弃 rename 改用 copy**（那会把原来的问题原样带回来）。
- **本批边界（必须说清，避免被读成更强的保证）**：
  - ✓ 消除 M2（半截/空文件）⇒ 并发读者不可能再读到坏 JSON。
  - ✗ **未消除 M1（丢更新）**：两进程各读旧、各写新，后写覆盖先写。真实 CLI 3 轮并发实测 **3/3 只存活 1 个槽**（预期，批 2 修）。
  - ✗ **未消除 M3**：版本不符 / CORRUPT 仍覆盖写回且无备份（批 3 修）。
- **★ 一处必须诚实说明的归因边界**：真实 CLI 的 5 轮并发对照中，**旧写法的 `invalidJson` 也是 0**。CLI 的读窗口只有微秒级，
  低频并发区分不出两种写法 ⇒ **不能拿 e2e 的 0 当作批 1 的证据**；M2 的证据只来自 `prove-m2.cjs` 的高频受控实验。
- **闸门**：437 → **442**（+5）。变异 **6/6** 全部按预期打红目标用例（调用点回退 / 先写目标 / 临时文件跨目录 / 失败不清临时文件 /
  不可重试当可重试 / 清理不保护本进程）。核心用例用**可注入钩子**在「tmp 已落盘、rename 未发生」处读主文件，
  断言读到的仍是**完整旧内容** —— 确定性证明，不靠 sleep 拼竞态（本机 sleep 拼法必然不可靠）。

### 三、状态文件写前重读合并（2026-10-24，批 2/4）：把丢更新率从 100% 压到约 20%

- **病灶**（批 1 明确留下的 M1）：`buildState` 的 `prevFile` 决定「保留其他主题的槽」，而调用方手里那份是
  **run 开始那一刻**的快照。一次 run 中间隔着整批站点请求与多轮迭代（分钟级），期间别的进程新建的槽会被这份陈旧快照覆盖。
- **修法**：`iterateRounds` 不再自行定稿，改为回传 `stateInput`（`cross` / `convergence` / `fingerprint`，**不含** `prevFile`）；
  新增 `writeStateWithMerge()` 在**紧邻写盘**处完成「重读 → 重建 → 写前二次确认 → 原子写」，
  发现期间被人写过（内容指纹变化）就**丢掉本轮结果重来**（`STATE_WRITE_TRIES = 4`）。
  重试耗尽则用最新内容重建后**强制写**，并把 `forced: true` 与 `writeAttempts` 透出到报告与 stderr —— 静默失败比丢更新更糟。
- **实测（真实 CLI，两个进程并发跑不同主题，共用同一状态文件）**：

  | 版本 | 样本 | 丢槽（只剩 1 个槽） | 成功率 |
  |---|---|---|---|
  | 批 1 后（无重读，仅原子写） | 8 轮 | **8** | 0% |
  | 批 2 后（CAS 重读合并） | 20 轮 | **4** | **80%** |

- **★ 判据未达标（必须写明）**：批 2 原定判据是「3 轮并发 3/3 存活 2 槽」，实测 20 轮里有 4 轮只剩 1 槽。
  **这不是实现疏漏，而是无锁「读-改-写」的理论边界**：CAS 只能发现「自己读之后」的变更；
  两个进程若几乎同时读、同时确认、同时写，都会通过校验 —— 文件系统没有可用的比较并交换原语。
- **★ 修正一处此前的错判（重要，影响后续排期）**：原计划认为「显式锁必须覆盖整次 run ⇒ 第二个进程要么等几分钟、要么失败」，
  据此把锁降级为「批 4 条件触发」。**这个判断是错的**：状态文件只在**最后**写一次，读可以重复，
  所以锁只需覆盖「写前重读 → rename」这一段**毫秒级**窗口，不需要覆盖整次运行。
  换句话说，锁的成本比原判低两三个数量级，收益却是「从 80% 到 100%」。
- **闸门**：442 → **448**（+6，其中 1 条改写）。变异 **6/6** 全部按预期打红**目标**用例
  （不回传 stateInput / 用空快照 / 忽略 prevFile / 指纹混淆 null 与空对象 / 去掉二次确认 / forced 恒 false）。
  两条关键用例是**行为测试**而非源码守卫：`writeStateWithMerge` 接受可注入钩子，在「重建之后、二次确认之前」制造一次写入，
  确定性断言「会重试且对方新建的槽被保留」—— 不靠 sleep 拼并发时序。
- **仍然不做**：改数据格式（追加式日志能天然避免丢更新，但要迁移全部状态文件，收益与风险不成比例）。

### 四、状态文件互斥锁（2026-10-24，批 3/4）：丢更新率 20% → 0

- **为什么原子写 + CAS 都不够**：批 1 消除「读者读到半截」（M2），批 2 的 CAS 只能发现「**自己读之后**」的变更。
  两个进程若几乎同时读、同时确认、同时写，**双双通过校验**，后写的仍覆盖先写的。
  文件系统没有「比较并交换」原语 ⇒ 无锁的读-改-写做不到零丢失。这是理论边界，只能靠互斥。
- **★ 推翻自己此前的排期判断**：原计划把「显式锁」降级为条件触发，理由是「锁要覆盖整次 run ⇒
  第二进程得等几分钟、残留锁会成为新故障模式」。**这是错的**：状态文件每次 run 只在**最后**写一次，
  且读可重复 ⇒ 临界区天然只有**毫秒级**，锁根本不需要覆盖整次运行。成本比原判低两三个数量级。
- **实现**：新增 `scripts/lib/file-lock.cjs`（纯 LF，162 行）。
  - 互斥来源 = `openSync(path + '.lock', 'wx')`（`O_CREAT|O_EXCL`），**这是唯一可靠的进程间互斥原语**。
  - 放锁**必须校验 token**（锁文件内的 pid + 随机串）：TTL 抢占后原持有者会来放锁，不校验就会删掉抢占者的锁。
  - 崩溃兜底 = **mtime + TTL**（10 s）。★ **不能用 pid 判活**：`process.kill(pid, 0)` 在 Windows 上走
    `TerminateProcess`，**会把被探测的进程杀掉**，返回值还是「已死」——探活动作本身成了故障源。
  - 同步等待用 `Atomics.wait`（`busy loop` 烧 CPU，`setTimeout` 拿不到同步语义）。
- **fail-closed**：等锁 3 s 拿不到 ⇒ **不写状态**并打 stderr 告警（带持有者 pid + 锁路径）。
  理由：丢一轮「记忆」可以重算，无锁覆盖别人的槽是**不可逆**的数据丢失。
- **临界区只包含**「重读 → buildState → 二次确认 → rename」；渲染、站点请求都在锁外。CAS 与原子写保留，
  作为「锁被 TTL 抢占 / 有人绕过锁直接写」时的兜底。
- **实测（真实 CLI 双进程、不同主题、共用状态文件）**：

  | 版本 | 样本 | 丢槽轮数 | 成功率 |
  |---|---|---|---|
  | 批 2 后（原子写 + CAS） | 20 轮 | 4 | 80% |
  | **关锁对照**（临时旁路 acquire，同一装置） | 10 轮 | 2 | 80% |
  | **批 3 后（加锁）** | **30 轮** | **0** | **100%** |

  ★ 关锁对照是本条的**必需部分**：没有它，30 轮 0 丢可能只是样本运气；对照复现出 80%（与批 2 的 20 轮 4 丢一致）
  才能把「0 丢」归因到锁。
- **闸门**：448 → **454**（+6）。变异 **7/7** 全部打红**目标**用例：
  互斥来源降级为普通创建 / TTL 把「存在」当「崩溃」/ 从不抢陈旧锁 / 放锁不校验 token /
  `withLock` 去掉 `try/finally` / 拿不到锁降级为无锁写 / 放锁移出 `finally`。
- **★ 两处判据自身的错误（提交前被自己拦下）**：
  ① 源码守卫断言「不得出现 `process.kill`」，但它**命中了自己头注释里为说明禁忌而写的字面量** ——
  自指陷阱第三次 ⇒ 守卫改为先剔注释再匹配（只认代码）。
  ② 「陈旧阈值 ≥ 5 倍等锁上限」是我凭空定的比例，实际 10 s / 3 s 是 3.3 倍。真实约束是
  「阈值远大于毫秒级持锁」「等锁上限不短于 1 s」⇒ 改为可辩护的形式，而不是为迁就断言去改常量。
- **★ 变异体也必须结构完整**：L6 首版写成 `if (false)`，变异体自己崩在 `got.handle` 上，闸门确实红了
  但**不是我预期的那条断言**（批 1 的 M6 同款误判）。换成「降级为无锁直接写」这种真实错误后才命中
  「拿不到锁却报告写成功」。**打红 ≠ 打红目标断言**。

### 五、不可用状态文件覆盖前先备份（2026-10-24，批 4/4）：`.corrupt-` / `.legacy-` 加 UTC 时间戳后缀

- **实测推翻了原判断的一半**：原挂账写「版本不符 / CORRUPT 仍覆盖写回且无备份」，暗示两者都丢数据。
  同一装置实测（`.verify/prove-m3.cjs`，20 槽）：

  | 场景 | 槽数 | 结论 |
  |---|---|---|
  | `corrupt`（截断 40%） | 20 → **1** | **丢 19 槽**，5,062 B → 497 B，无任何备份 |
  | `legacy`（version=3，合法 JSON） | 20 → **20** | **不丢槽** —— `buildState` 的 `slotsOf` 不校验版本 |

  ⇒ 「版本不符会丢数据」是**错的**，不能这么写。但 REJECTED 另有一处自相矛盾：`readPrior` 的理由是
  「格式语义可能已变 ⇒ 不合并」，`buildState` 却照样按旧语义把槽搬过去 —— 一旦对方格式真变了，
  搬过去的就是被静默曲解的槽。**两条分支都要备份，但措辞必须分开**（前者是数据丢失，后者是语义存疑）。
- **修法**：`converge-state.backupNameFor()`（**纯函数**，该模块零 IO 的守卫不受影响）给出
  状态文件旁的 `.corrupt-` / `.legacy-` 备份名（后缀为 UTC 时间戳）；`rank-records.backupUnusableState()` 在
  **锁内、第一次写之前**把原文件逐字节留档（`'wx'` 独占创建 + `fsync` + 撞名按序号退让）。
- **★ 三条不可省的细节**：
  - 备份写**原始字节**（`readFileSync` 不带 encoding）：要救的正是「解析不了」的那份，解析后重新序列化等于没救。
  - 备份失败 ⇒ **fail-closed 不写状态**（`skipped: true, backupFailed: true` + stderr 指明磁盘/权限）。
    救不了就别毁 —— 与批 3 锁超时的处置同一原则。
  - 只对 `corrupt` / `rejected` 备份；对 `ok` / `none` 也备份会每轮堆积无用文件。
- **可见性**：成功时 stderr 打 `[提示] 旧状态文件不可用（解析失败|版本不符），已原样备份到备份路径（N B）后重建`；
  失败时打 `[警告] … 本轮不写状态记忆 …`。异常不能只躺在 JSON 里等人去翻。
- **本批边界**：备份是**留档**，不是自动修复 —— CORRUPT 时活文件仍会被重建成 1 槽（解析不了就无法合并），
  恢复只能人工从备份取回。不做「猜格式抢救」，那会引入比丢失更糟的静默错误。
- **闸门**：454 → **459**（+5）。变异 **6/6** 命中目标断言（删调用 / 备份挪到写之后 / 备份失败仍写 /
  `'wx'`→`'w'` / 对 ok 也备份 / 备份建了但内容为空）。B2 的变异体由脚本从源码**机器构造** ——
  手工敲 20 行长块必出 typo，而 typo 造成的 SETUP-FAIL 会被误读成「判据无效」。

### 一、资料库 direct-edit 预检：同锚点多条插入会倒序落位（`lib/doc-actions.cjs`）

**为什么做**：2026-10-21 实测，**61 条同锚 `insert_after` 提交后落成「十八…十四」**——与数组顺序完全相反。

**记忆不会让机器拒绝错误输入**，下一个人（或下一次的我）仍可能把 3 个块拆成 3 条 action 提交。

**判据（以 14 份真实 actions JSON 为样本；`type` 实测只有三种）**：

| 判据 | 取值 | 依据 |
|---|---|---|
| 冲突定义 | 同锚点 + **`insert_after`** ≥2 条 | 倒序实测只发生在 after；before 为正序（见下） |
| `delete` 是否参与 | 否 | 其 `id` 是「被删块」而非锚点 |
| 未知 `type` | 显式报错 | 新 type 不得静默逃过判据 |
| 正解 | **一条** action + `content` 空行串联 | `planInsert`：块数守恒 + 保序 |

- **★ 方向性是实测结论，不是推测**（2026-10-24，临时页 `dGLW5PdQigMjD3PHsKuyxf`）。

  |---|---|---|---|
  | `insert_after` | 2 | **倒序** | 复现 2026-10-21 事故 |

## [v4.10] — 2026-10-21 — Europe PMC 全文通道（B→A 的唯一路径）

**为什么做**：摘要级判定拿不到两样东西 —— ①**设计与统计的原文**（随机化/盲法/交叉/洗脱/统计方法），
它决定证据能否从 B 升 A；②**资助方与 COI**，它决定结论该被读多重。
实测 `PMC13255985`（Animals 2026，膳食钾）全文 **113,385 字节** JATS XML、`license: cc by`、`hasPDF: Y` —— 免费可取。
而旧版 `enrich.cjs` 只读了 `isOpenAccess` 就停下：**已知「这篇 OA」，却没有 pmcid ⇒ 拿不到全文入口**。
更关键的是，`pmcid`/`hasPDF`/`license`/`fullTextIdList` 与 `abstractText` 在**同一个 `resultType=core` 响应体里**
⇒ 这是**零新增请求**就能补上的洞。

### 新增（A · 零请求字段补全，`enrich.cjs`）
`enrichOne` 的返回增补：`pmcid` / `hasPDF` / `license` / `inPMC` / `citedByCount` / `pubTypes` / `funders` / `fullTextUrl`。
- `hasPDF`/`inPMC` **缺失时留 `null`，不得写 `false`** —— 否则「确认没有」与「EPMC 没告诉」混为一谈。
- `funders` 取自 `grantsList.grant[].agency`（实测 `Hill's Pet Nutrition (United States)`）。
  它**不参与证据分级**（分级只看设计与终点），但必须在报告里可见。
- `fullTextUrl` 优先取 OA 的 **html**，其次 OA 的 pdf，最后按 pmcid 拼 europepmc 页。
- ★ `fullTextIdList` 是**嵌套对象**（内部含 `fullTextId` 数组字段）而非数组；`fullTextUrlList.fullTextUrl` 才是数组 —— 两者形态不同。

### 新增（B · 可选全文通道，`lib/fulltext.cjs`）
- `--fulltext`（**依赖 `--enrich`**，缺依赖时显式报错，不静默空操作）+ `--fulltext-concurrency`（上限 4，默认 2）。
- 抓 `fullTextXML` 端点（路径参数为 PMCID），落盘 `fulltext` 目录下以 PMCID 命名的 txt（文本化全文，**偏移回查的唯一载体**）+ `.json`（抽取结果）。
- 抽 9 类方法学信号：随机化 / 分配隐藏 / 盲法 / 交叉 / 洗脱 / 样本量 / 统计方法 / 对照组 / 重复测量。
- **幂等**：`txt` 与 `json` 同时存在直接复用（实测第二次 2ms、`cached:1`），不重复下载 113KB。

### 三条纪律（写进模块头注释，也写进自测）
1. **只补信息，不改等级**。本模块不产出、也不允许产出 `evidenceLevel`；抓取失败**绝不**降级。
2. **偏移量必须可回查**。`offset` 相对 `xmlToText()` 的产物，而该产物原样落盘为 `.txt`
   ⇒ 用 offset 在 txt 里切片必须逐字等于 JSON 里的 `matched`（自测逐条断言，真实数据 5/5 通过）。
3. **不猜**。定位不到方法学节时 `methods = null`，不拿 Introduction 片段冒充；信号不在方法学节内则标 `scope: 'body'`。

### 本轮抓到的四个真 bug（自测/端到端/实测各抓一部分）
1. **成功路径漏写 `status`**：`brief()` 不含 status，只有**缓存路径**写了 `status:'ok'` ⇒ 新抓的记录反而不显示方法学信号。
   自测只覆盖失败路径时抓不到，**靠真实端到端暴露**。修：成功路径也写 `status:'ok', cached:false`。
2. **`3. Results` 匹配不到**：节标题带编号，`^(results?)` 锚点失效 ⇒ 方法学节一路吞到文末（27,150 → 实际应为 8,409 字符）。
   修：允许前导编号 `^(\d+(\.\d+)*\.?\s*)?`。
3. **`p = 0.3` 被当成统计方法**：`statistics` 正则含 `p\s*[<=]`，而 p 值属**结果**、且在方法学节里常先出现。
   修：只认 `statistical analyses` / `ANOVA` / `mixed-effects` / `t-test` 等，不含 p 值。
4. **`randomly assigned` 未覆盖**：原文写 `randomly divided`/`randomly assigned` 而非 `randomized`，原正则漏掉。
   修：补 `randomly (assigned|allocated|divided)`。
另修正一处设计：信号原取「全文首个命中」，会把**摘要**里的 `cross-over` 当方法学（实测 off=1974）；
改为**方法学节内优先**，节内没有才退到全文并如实标 `scope:'body'`。

### 报告侧（`assemble-report.cjs`）
- 汇总新增「**全文通道**」行：`有 PMC 全文 N / 总数，已取 N（新抓 + 缓存），失败 N，OA 但无 PMC 全文 N 条`。
- **矛盾态单列**：`isOA=true` 却无 `pmcid` 的记录拿不到任何全文入口 ⇒ 报告明写，并注明这属 EPMC 与出版社口径不一致、**不是抓取失败**。
- 单条增 `全文: [PMC…](url) · 许可 cc by`、`资助方: …（COI 参考，不参与分级）`、
  「**方法学信号**」表（含 `@offset`，指向该 txt）。
- 抓取失败的条目显示 `_全文: error:404（未取得；**等级不因此改变**）_`。

### 自测
新增 **19 项**（336 → **355**），含：`xmlToText` 实体不二次解码 / 确定性 / 方法学节不越界 / 无节返回 null /
方法学节内优先 / 退到 body 不冒充 / **偏移逐条可回查** / statistics 不命中 p 值 /
`--fulltext` 缺 `--enrich` 报错 / 并发度越界 / enrich 八字段补全 / 字段缺失为 null / fullTextUrl 取 OA html /

### 三条诚实约束在图上的落法
- **「未读到」≠ 0**：合计节点换警示样式（`pd-value-warn`）并在下方明写「合计偏低：N 个检索式未读到计数（不等于 0 命中）」，脚注列出具体检索式。真 0（`zero_confirmed`）**不得**触发这些字样。

- **未去重（`duplicatesRemoved = null`）≠ 0**：显示「未执行」+「null ≠ 0」。资格段的「工具自动排除」以虚线旁注呈现并标注「本工具不做资格判断」；复核标记同样以旁注呈现并标注「含在纳入内，非排除」。

### 写盘顺序（本轮踩过）
必须 **先算图 → 再写图 → 最后写 md**。因为 md 里的 `![](PRISMA.svg)` 要与实际落盘一致；
若先写 md 再出图，一旦图失败，md 就带着**断链引用**，读者看到的是破图而不是「请以 ASCII 版为准」。

### 本轮抓到的三处真 bug（都是验证环节抓的，不是写的时候想到的）

1. **`Number(null) === 0`**：`validateFunnel` 初版只判 `Number.isFinite(Number(val))`，
   于是「计数缺失」被判合法并**画成 `0`**。这正是本项目反复强调的「null 当 0」，只是这次犯在出图这一层。
   修法：先显式拦 `null`/`undefined` 再谈 `isFinite`。
2. **真实检索式让脚注溢出画布**：真实检索式长 90+ 字符，直接拼进「未读到」脚注会把文字推到 **x≈1251**（画布仅 900），
   渲染时整行被裁掉 —— 而「未读到的是哪几条」正是这条脚注存在的全部理由。
   修法：`unknownClause()` 按像素预算收口，放不下就截断词本身，但**始终保留「共 N 条」与「≠ 0 命中」**两个不可省语义。
   *（此条由几何越界校验抓出：`xml.etree` 只能证明是合法 XML，证明不了文字没越界。）*
3. **预算按未转义文本算 ⇒ 仍然溢出**：修完第 2 条后仍超 111px。根因是 `"` 在 SVG 里转义成 `&quot;`（1 字符 → 6 字符），
   实测 4 个引号就让宽度虚增约 116px。修法：预算估算必须作用于**转义后**的字符串。

### 验证方式（为什么不是靠肉眼）
截图接口对本地预览页返回超 10 MiB 限制（三种尺寸都失败），故改用两道机检：
`xml.etree` 严格解析（well-formed）+ 自写**几何越界校验**（G1 label 不压数字 / G2 旁注不压数值 / G3 y 在画布内 /
G4 注记不越框 / G5 右对齐不越左 / G6 任何文字不越右）。
几何校验本身先用「真实长检索式」证伪过 —— 它必须能红，才配被用来判绿。

### 自测
新增 **22 项**（313 → **335**），含四组不变式的「篡改必红」、三态不可互换、真 0 不误标、XML 转义（标签开合自洽）、

### 八、新增能力：覆盖诊断「缺词候选」`suggest.cjs`（把「覆盖」也半自动化 · 最佳档执行结果，2026-10-16）

- **动因**：「七」的结论是**形态靠代码、覆盖靠人**，而「覆盖」原本只能靠人通读题名。本轮把「缺词」变成机检信号。

### 九、新增能力：补词闭环 `--apply`（勾选后重排 + 效果对比 · 最佳档执行结果，2026-10-16）

- **动因**：八把「缺词」变成了可勾选清单，但「补进去到底有没有用」仍要手工再跑一次并肉眼比对。
  本轮把这段接成闭环：**显式勾选** ⇒ 并入词表 ⇒ **原地重排**（只读同一批 `raw/*.json`）⇒ 输出对比小节。
- **实现（两处，均为纯函数 / 零站点请求）**：
  - `scripts/lib/relevance.cjs`：`mergeTerms(base, add)` — 词表合并（等值去重按 `compactKey`，
    故 `肾脏` 与 `腎臟` 是同一词；原词保序在前、新增在后）；`diffRanks(before, after, opts)` — 重排对比。
  - `scripts/rank-records.cjs`：`--apply` 参数（取值 = 勾选词，逗号分隔）+ `renderApplyDiff`
    （对外返回**字符串**，与 `renderMarkdown` 契约一致）+ md 内嵌小节 + json `applyDiff` 字段。
- **配对键 = keyword + idx + 题名 + 年份**（**不含 rank** —— rank 会因换词表而整体重排）。
  为何含 keyword/idx：未去重时同一文献会出现在多条检索式下；仅凭题名+年份会错配。
  `unmatched` 同批数据必须为 0，非 0 时**照实报出**（「两次排序不是同一批数据」）而非静默。
- **★ 不变量（可断言）**：补词只会增加命中 ⇒ 分数单调不减 ⇒ **降级必为 0**。
  对比小节照实报出降级并标为**缺陷信号**（不掩盖、不当正常波动）。
- **★ 本轮最重要修复（真实数据抓出，非推演）**：`mergeTerms` 初版经 `splitList` ⇒ 被 `normalizeTerm`
  **改写了用户原写法**（实测 gutkidney 输出串把 `SCFA` 写成 `scfa`）。匹配层本就不分大小写 ⇒ 功能等价，
  但**可追溯性受损**（用户比对原值时会以为词表被改）⇒ 改为**只 trim、不做任何形态归一**。
  先红断言（`实际 ["scfa","dietary fiber",...]`）→ 修复 → 变异 M14 转红。
  ⇒ SKILL.md 已写明两种形态的分工：**词表 v2 = 原文（供粘贴）**；头部「主题词」与表格命中列 =
  **归一形态（匹配用）**，两者不可混读。
- **★ 第二条纪律实证**：断言 14 的源码守卫初版只查「已全部在」四字，而 **HELP 文本里也有这四个字**
  ⇒ 单点变异（改 fail 消息）**打不红**（M13 盲区）。⇒ 守卫必须限定到**语义位置**：
  即「appended 为空 ⇒ 走 fail 分支、且该分支的消息含此提示」这一**结构 + 内容**组合，而非孤立查四字。
  这与「父子遮蔽伪造绿灯」同族 —— **判据读到的元素不是它以为的那个**。
- **验证三段**：
  - **闸门 190 → 204**（+14 条；其中 13 条来自本轮新增，另 1 条为「保原文形态」修复）。
  - **变异 14/14 全部转红**（跨两文件），还原后 sha256 **逐字节一致**；期间抓出 1 个真盲区（见上）。
  - **真实数据闭环**（gutkidney 同批 40 条，仅换词表、**站点零请求**）：

    主题命中 **14 → 15**、命中率 **35% → 37.5%**、降级 **0**、配对 40 条（未配对 0）。
- **闭环的附带价值**：补词后覆盖诊断**不再提示刚补进去的词**（已覆盖判定基于词表 v2），
  剩下的候选即「下一轮可补的词」—— 形成可迭代的收敛过程。
- **已知边界（如实登记）**：`--apply` 只扩展**主题词**（`--near` / `--exclude` 不变）；

### 十、新增能力：多轮迭代闭环 `--iterate`（回答「还能挖到多少」· 最佳档执行结果，2026-10-17）

- **动因**：九的 `--apply` 只答「补这几个词有没有用」，答不了**上限**：
  这个词表继续补下去能达到多少、需要几轮、**补完之后还剩什么治不了**。
- **实现**：`scripts/lib/iterate.cjs`（**v1**，纯函数 / 零网络 / 零文件系统 / 显式 `stationRequests: 0`）
  + `rank-records.cjs` 的 `--iterate` / `--iterate-batch` / `--iterate-pick` 与 `renderIterateReport`。
  词表合并**必须**复用 `mergeTerms`（源码守卫钉死，禁止第二套去重语义）。
- **★ 定位约束（本能力的核心纪律）**：迭代会**自动**批量取词 ⇒ 产物**不代表建议词表**。
  故报告首句、标题、词表块标题**三处冗余**声明「模拟 / 不代表建议词表 / 待人工确认」——
  人眼极易只读到其中一处。`--iterate` 与 `--apply` **互斥**（探测 vs 采纳，语义相反）。
- **★ 三档分工（诚实结论：没有「既不漏真词、又不进残渣」的自动档）**：
  - `all`（默认）＝ 全取候选 ⇒ **词表覆盖率天花板**（数字可信、词不可信）
  - `extends` ＝ 只补「词表词的延伸」⇒ **安全增益**（词可用，但常常为 0）
  - `--apply` ＝ 人工挑词 ⇒ **唯一可信通道**
  区间不可自动化的原因：`overlapsTopic` 那类候选里，`菌群代谢`（真缺词）与 `慢性肾`（错位片段）
  **形态同构**，纯 n-gram 无法区分 ⇒ 只能交人。
- **★ 读数的硬边界**：`all` 档的命中率是**覆盖率达 95%**，不是**主题相关性 95%** ——
  候选来自题名 ⇒ 补进去必然命中 ⇒ 数字必然逼近 100%。gutkidney 实测 35% → **95%（6 轮饱和、补 25 词）**，
  但其中 `慢性肾`／`性肾衰竭`／`道菌群代`／`犬血` 均为分词错位片段。
- **★ 新增 `residual`（收敛后仍非主题命中的记录）—— 本能力真正有用的产物**：
  它把「补词治不了」的记录单列，标注为**结构性缺口（缺主题维度）**而非又一份补词建议。
  gutkidney 实测 2 条，其中《猫慢性膀胱炎合并肾炎病例的诊治》（2013）属「猫泌尿 + 肾脏」临床维度，
  与「肠-肾轴 × 菌群」不同轴 ⇒ 须新增主题维度。**这条价值大于整张命中率曲线。**
- **停止原因穷举四种**（不得出现「说不清的停止」）：`no-candidates` · `no-gain` ·
  `max-rounds` · `all-covered`（防御性：跨模块去重语义一致性的防线，理论不可达 —— 保留并注明理由，
  因为一旦 suggest 与 mergeTerms 的归一规则将来分叉，它就是第一道警报）。
- **验证三段**：
  - **闸门 204 → 218**（+14 条：13 条迭代判据 + 1 条 `residual` 判据）。
  - **变异 15/15 全部转红**（跨两文件），还原后 sha256 **逐字节一致**。
  - **真实数据闭环**（gutkidney 同批 40 条，站点零请求）：35% → 95%，6 轮饱和（第 6 轮 `no-candidates`），
    每轮降级 **0**、主题命中**单调不减**、词表**单调增长**。
- **★ 本轮抓出的 3 个真盲区（都是"断言看起来在测，其实什么也没测"）**：
  1. **batch 断言是装饰**：夹具记录初始全为 off，而 `scope=near` 的语料不含 off ⇒ 候选为空 ⇒
     `rounds[0].appended` 为空 ⇒ `every(...)` 的**空真值**让断言永远通过。
     ⇒ 夹具改为 `scope=all`，并**额外断言「夹具须真产生补入」**（防止将来再次退化）。
  2. **穷举断言未覆盖 `max-rounds` 分支**：三个 case 都提前停了 ⇒ 变异注入 `stopReason='done'` 时
     穷举断言照绿。⇒ 补一个必然跑到循环结束的 case，并断言「用例须覆盖 max-rounds」。
  3. **互斥守卫只查消息文本**：变异把 `if (o.apply)` 改成 `if (false)`、消息保留 ⇒ 守卫照绿。
     ⇒ 改为「条件 + 消息」的结构化正则（与九的 M13 同一教训，**第二次踩** ⇒ 已提升为通用纪律：
     源码守卫一律「语义位置」而非孤立字符串）。
- **已知边界（如实登记）**：`pick=extends` 只认「候选包含某个**主题词**」——
  若真缺词恰好是**相邻词**的延伸（`肾脏` 在 near 里），它不会被自动补，会进 `deferred`。
  本批实测 `extends` 补 0 词（19 个候选全为半重叠类），即该主题**没有可安全自动补的词**。
- **产物**：`demo-iterate-20261017/mutate-iterate.py`（15 变异 · 双文件自证）·
  `demo-gutkidney-20261016/dedup/ranked-iterate8.*`（8 轮上限探测，内含逐轮增益 + 残留清单）·

- **未做**：多轮迭代的**人工闸门**（每轮停下来等人确认再继续 —— 当前是一次跑完再人工读，属设计取舍）；
  `--near` / `--exclude` 的迭代扩展。

### 十一、新增能力：残差维度诊断 `diagnose.cjs`（把 `residual` 从「清单」变成「缺哪个维度」· 最佳档执行结果，2026-10-18）

- **动因**：十的 `residual` 只答「**哪些**记录补词治不了」，答不了「**缺的是哪个维度**」。
  人拿到一份 20 条残留清单仍要逐条通读 —— 十的产物把问题定位到了「结构性缺口」，本条负责把缺口说清楚。
- **实现**：`scripts/lib/diagnose.cjs`（**v1**，纯函数 / 零网络 / 零文件系统 / 显式 `stationRequests: 0`、
  `autoApply` 恒 `false`）+ `iterate.cjs` 收敛后自动挂 `diagnosis` + `rank-records.cjs` 的 `renderDiagnosis`
  （md 内嵌进 `--iterate` 报告）与 JSON `iterate.diagnosis`。**未新增任何 CLI 参数**（诊断随 `--iterate` 自动产生）。
- **★ 铁律：只提示，不自动建**。提案 `proposal.keywords` 永不回流词表（源码守卫 + 单测双向钉死），
  采纳唯一通道仍是 `--apply`。理由：补词只影响召回宽度；**新增主题维度会改变「什么算相关」**——必须人拍板。
- **簇语义两分**：`new-dimension`（与词表/相邻词**零 ≥2 字重叠**）vs `axis-extend`（同轴写法差异，
  补词可治）。种子排序**新维度优先**：若按 df 全局贪心，轴内高频词会先把含新维度词的记录吞掉，
  新维度整簇消失（变异 M1 实证：改回 df 优先后该用例立刻转红）。
- **三道闸（每条都对应一次真实假阳性）**：
  1. 簇内 ≥ `minSupport`（默认 2）条 —— 个案不是维度；
  2. 簇内**至少 2 个共享指纹**（`no-cohesion`）—— 一手证据：猫毛球 10 条全 off 时，
     `生物`（合成生物学／生物安全／生物风险）与 `肠道`（肠道寄生虫／肠道菌群）各聚出 2~3 条，
     簇内再无第二个共享词 ⇒ 泛学术词拼出的假维度。**把「同一主题」从「一个词」抬到「两个词」**；
  3. 极大剪枝（与 `suggest` 同规则）—— 同时解决「物种前缀粘连」：`猫膳` ⊂ `猫膳食纤维`，
     不剪则簇标签退化成「物种字 + 半个词」，且因与轴零重叠被误判为新维度（M2 实证）。
- **口径**：一条记录只归一个簇 ⇒ `support` 之和 ≤ 残差数（可对账）；剪枝**不回流**（不级联重分配，
  避免顺序依赖）；被剪记录逐条列出并标原因 `no-shared-term` / `spun-off` / `no-cohesion`。
  `verdict` 四态：`no-residual` / `no-shared-terms` / `axis-only` / `new-dimension`。
- **★ 为何没有 covered / exclude 过滤（不是漏写，是不可达）**：`rankAll` 规则为「题名含主题词 ⇒ exact」，
  排除词记录另走 `excluded` 档且被本模块跳过 ⇒ 两种情形在语义上都不存在。该前提由单测
  「不变量守卫」显式钉住（`rankAll` 改档位规则时先红的应是那条守卫，而不是诊断结论）。
- **实测（站点零请求）**：
  - gutkidney 全词表 8 轮收敛后 ⇒ 2 条残差互不相关，判 `no-shared-terms`（**不硬凑**）；
  - 零回归证明：与 2026-10-17 的 `ranked-iterate8` 逐字段比对，`final` / `terms` / `stopReason` /
    `totalGain` / 逐轮命中数 / 逐条档位**全部一致**（唯一差异是旧产物把 `SCFA` 归一成 `scfa`，
    属十之前的旧口径，已单独钉成断言）；

  - **正例**：词表收窄到 5 个中文词（`肠肾轴,肠道菌群,短链脂肪酸,膳食纤维,益生元`）⇒
    聚出 `Kidney` 簇（5 条 / 强证据 / 术语 `Kidney`、`Chronic Kidney`、`Axis`），
    正确指认「英文 kidney 轴缺失」。
- **★ 已知边界（如实登记）**：① 稀疏维度（仅 1–2 篇）按设计识别不出来（个案不是维度）——
  实测把 `益生菌/益生元` 整组挖空后**未被认回**（相关文献 1–2 篇）；② 泛词仍可能通过凝聚度闸门

### 十二、新增能力：建议检索式 `query-plan.cjs`（把维度诊断接成「下一步搜什么」· 最佳档执行结果，2026-10-18）

- **动因**：十一答了「缺哪个维度」，但人拿到「新维度 = `Kidney`」之后仍要自己想「拿什么式子去验证它」。
  而且十的实测已经证明：**真问题常在检索式层**（猫毛球 10 条全 off，病因是召回过宽），词表层补不回来。
- **实现**：`scripts/lib/query-plan.cjs`（v1，纯函数 / 零网络 / 零文件系统）+ `iterate.cjs` 把结果挂到
  `diagnosis.queries` + `rank-records.cjs` 的 `renderQueryPlans`（md 独立一节）与 JSON `iterate.diagnosis.queries`。
- **★ 铁律一：只出方案、不执行**。`executed` 恒 `false`、`stationRequests` 恒 0，模块内无任何自动跑分支；
  每条式 `verified: false`。理由：检索是有成本的动作（积分/配额），「值不值得再搜一轮」是人的判断。
- **中英分条**：中文术语配中文物种块、英文术语配英文物种块（站点是中英双语库，一条式盖不住两侧索引）。
  物种块复用 `build-queries.cjs` 的 `SPECIES`，语法校验复用其 `validateQuery` —— **语法规则只有一份**。
- **物种探测**：`--species auto`（默认）按题名探测 `cat` / `dog` / `both`。规则是**宁宽勿窄** ——
  两者都出现或都不出现一律 `both`：漏物种块会大幅降召回，多带物种词只是多召回几条异种文献（后段还能挡）。
- **★ 术语去冗余**：若某术语是**另一术语的真子串**且不是簇标签，则不写进 OR。理由：OR 是并集，
  加子串只放宽召回、不增加定向性。一手证据：gutkidney 的 `Kidney` 簇里 `Chronic`（`Chronic Kidney` 的子串、
  全局 df 更高 ⇒ 极大剪枝按设计保留它）进了式子，等于「题名含 Chronic 即命中」，把式子直接稀释掉。
  簇标签必留（`Kidney` 也是子串，但剔掉就丢靶心）。
- **★ 物种粘连剪枝（`diagnose.cjs` v1 → v2 + `suggest.stripSpeciesAffixes`）**：n-gram 会产出
  `Canine chronic`、`猫膀胱炎` 这类「物种词 + 半个词」。它们作为**簇术语**是错的 —— 式内自带物种块，
  再带物种就得到「(cat OR feline) AND (Canine chronic)」这种自相矛盾的组合。
  - 判据（与极大剪枝同构，把「包含」换成「剥物种词素后相等/被包含」）：① 剩余串本身已入册且 df 不逊；
    ② 剩余串是另一入册指纹的**真子串**（`猫膳` → `膳` ⊂ `膳食纤维`）。
    ②不可省：极大剪枝会把 `膀胱炎` 吸进 `猫膀胱炎`，剪掉长串后 `猫膳` 会立刻冒出来占位
    （n-gram 的「按下去又弹起来」，与 `物犬` 同一现象；M10 变异实证）。
  - **顺序不可换**：物种剪枝必须在极大剪枝**之前**。极大剪枝的方向是「短串被长串吸收」，
    而这里要留的恰恰是剥掉物种词后的短串。
  - 因判据依赖「剩余串确实已入册/被入册串包含」，`catheter` → `heter` 不会被误剪（M12 反证）。
- **★ 凝聚度闸口径变更（`no-cohesion` 只对新维度簇生效）**：该闸防的是「把泛词当新维度」，
  同轴簇不产新维度提案、术语本就与现有轴重叠 ⇒ 无此风险。若一律套用，单共享词语料
  （三条题名只共用 `膳食纤维`）会从 `axis-extend` 退化成「归纳不出共同维度」的误报 —— 物种剪枝后实测暴露。
- **★ 根因修复：JSON 通道是逐字段白名单，漏字段不报错**。实现完成后真实 CLI 输出里**没有** `queries`
  （md 有、JSON 没有），而单测全绿 —— 因为用例直接喂 `iterateRounds()` 的返回值，绕过了 main 里的
  白名单映射。已把该映射抽成 `compactIterate()` 并让用例**走它**（M15 变异验证：删掉 `queries` 行即转红）。
  这类「测试绕过真实序列化路径」的盲区，比断言写错更隐蔽。
- **新增 CLI 参数**（只影响建议式，**不改排序**，单测双向钉住）：
  `--species auto|both|cat|dog|none`（默认 auto）· `--query-cap N`（每条式术语上限 1–8，默认 4）。
- **实测（站点零请求，三态齐全）**：
  - gutkidney 全词表 ⇒ 1 条英文式
    `(dog OR cat OR canine OR feline OR companion animal OR pet) AND (Kidney OR Kidney Disease OR Chronic Kidney OR Axis)`
    （`Chronic` 已剔并告警；`Axis` 无包含关系故保留，泛词风险由人工复核兜住）；

- **闸门**：单测 **232 → 247**（+15：纯函数/`executed`/`verified` · 语法合法 · 只给新维度出处方 ·
  原文形态 · 中英分条 · 物种探测四态 · 术语上限 · 多词短语告警 · 空簇不臆造 · 物种粘连必剪 ·

### 十三、处方实测 + 主题锚 `query-plan v2`（把「未实跑」变成实测结论 · 最佳档执行结果，2026-10-18）

- **★ 实测结论一：处方单独使用不提升主题命中**。判据 × 物料 2×2（语料 40 条）：

  | 基线 · 5 中文词 | 40 | 5 | 6 | 29 | 12.5% |
  | 处方并库 · 5 中文词 | 56 | 5 | 6 | 45 | 8.9% |
  | 基线 · 5 中文词 + `kidney` | 40 | 10 | 10 | 20 | 25.0% |
  | 处方并库 · 5 中文词 + `kidney` | 56 | 26 | 10 | 20 | 46.4% |

  只加物料 `exact` 5 → 5（**0 收益**，命中率反降）；只加判据 5 → 10；两者叠加 5 → **26（+21）**。
  ⇒ **处方与补词是合取关系**：处方给物料、补词给判据，缺一不可。

  | 无锚 `(cat OR feline) AND (Kidney OR … OR Axis)` | 54,100 | 16 | **1 / 16** | 1 | 15 |

### 十四、新增能力：维度收敛判据 `convergence.cjs`（同一维度不再被反复当「新发现」· 最佳档执行结果，2026-10-18）

- **动因**：十一/十二 的产物都只描述「**这一轮**缺哪个维度」。于是同一维度会在每份报告里重新出现一次，
  support 每次都是新的绝对值 —— 人看不出它是「还在」「在缩」还是「卡死」。缺的判据就是：
  **簇消失**（support 落到最小支持数以下 / 记录已升档）才算这个维度收敛。
- **做法**：`iterate` 逐轮做残差诊断（round 0 = 起始词表），按簇 key 跨轮追踪 ⇒ `convergence`。
  追踪用 `maxClusters=10`（诊断上报上限），报告仍用默认 5 —— 否则「被上限挤出的簇」会被误判成「已消失」。
- **判据（六态穷举，无「说不清」）**：

  | 状态 | 判据 | 含义 |
  |---|---|---|
  | `resolved` | 末轮观测中已无该 key | **收敛**（support 低于 minSupport 或记录升档） |
  | `stalled` | 末轮仍在，与上次观测 support 相等 | 补词治不了，属检索式/站点侧 |
  | `shrinking` | 末轮仍在，support 严格下降 | 仍在收敛中 |
  | `grew` | 末轮仍在，support 严格上升 | 反向（须核查语义是否漂移） |
  | `emerged` | 只有一次观测 | 趋势未知，不得当结论 |
  | `capped` | 末轮缺失，但末轮簇数超上报上限 | **无法判定**真消失还是被挤出 |

  收敛判定五态：`converged`（无 capped 且存活簇全 stalled）/ `converging`（有 shrinking）/
  `active`（有 grew/emerged）/ `inconclusive`（有 capped）/ `insufficient`（观测不足 2 轮）。
  **顺序即语义**：grew/emerged 优先于 shrinking —— 同时有「缩小的」和「长出来的」时不能判「收敛中」。
- **★ 实测（真实语料 48 条，站点 0 请求）**：

  | 词表 / 轮数 | 簇 | support 序列 | 状态 | 结论 |
  |---|---|---|---|---|
  | 5 中文词 + 6 相邻词 / 3 轮 | `Kidney` | 5 → 5 → 5 | `stalled` | 已收敛（补词治不了） |
  | 同上 | `调控` | 4 | `resolved` | 已收敛 |
  | 同上 | `慢性`（同轴） | 8 | `resolved` | 已收敛 |
  | `肠道菌群,膳食纤维` / 4 轮 | `Kidney` | 5 → 5 → 5 → 5 | `stalled` | 同上，卡 4 轮 |
  | 同上 | `调控` | 4 → 4 | `resolved` | 先卡后**落到阈值以下**（正是判据的第二条腿） |

  残差规模 37 → 23 → 23 / 37 → 28 → 24 → 24（单调不增 ✓）。
- **★ 一条订正**：`converged` 不等于「残差为 0」。残差非 0 但归不出共同维度（`no-shared-terms`）时，
  state 仍是 `converged`（**没有维度可收敛**），note 必须指向「这些记录须逐条人工判读」——
  否则会被读成「残差已覆盖」。该区分已落成断言（M16 变异可打红）。

### 十五、新增能力：跨运行收敛记忆 `converge-state.cjs`（同一维度只正经报一次 · 最佳档执行结果，2026-10-18）

- **动因**：十四的收敛判据只活在**单次运行内**。跨运行它就失明了 —— `Kidney` 今天 `stalled`、
  明天还是 `stalled`，每份报告都重写一遍、建议检索式也重给一遍。人读到第三遍时的自然反应是
  「早就知道了」，第四遍开始就不读了。缺的是**记忆**：这个维度是这次才发现，还是上次就报过且结论没变。
- **做法**：`--converge-state` 后面跟状态文件路径。运行结束把本次结论写进状态文件；下次运行读回，按
  **主题指纹**校验后合并，给每个簇贴 `trend` 与 `reportCount`。
  ｜IO 只在 CLI 层（读一次、写一次），`lib/converge-state.cjs` 是**纯函数**（源码守卫钉死：禁止 fs/net/子进程/`process.env`）。
- **五态 `trend`（穷举、互斥、无「说不清」）**：

  | 状态 | 判据 | 含义 |
  |---|---|---|
  | `new` | 历史无该 key，本次有 | 首次报告 |
  | `persistent` | 上次活着，本次还活着 | **结论没变**（抑制的候选） |
  | `resolved` | 上次活着，本次末轮缺席但本次出现过 | 刚收敛 |
  | `cleared` | 上次活着、本次连出现都没有；或上次已收敛、本次仍没有 | 彻底消失 |
  | `recurred` | 上次**已判收敛**，本次末轮仍在 | **回归**（警示：上次的收敛不可信） |

- **★ 唯一不可让步的闸门：主题词表变了 ⇒ 拒绝合并**。不同词表是不同的问题定义，
  沿用旧结论会造出「这个方向已经查过」的假记忆 —— 这比「少给一次建议」危险得多。
  词表的**顺序**变化不算换主题（规范化时排序后比对）；语料规模变化**不**拒绝（新增文献是正常演进），
  但标记 `corpusChanged` 并告警 —— 否则 support 变动会被误读成补词效果。
- **抑制（「只报一次」的落地）三条腿缺一不可**：`persistent` + `stalled` + `reportCount ≥ 2`。
  缺任一条都不抑制：结论变了要报（support 动了）、刚回归要报（警示）、第一次要给式子。
  抑制必须**显式记入 `suppressed`** 并在报告里点名 —— 「这次没给建议」与「没有建议可给」不是一回事。
- **确定性**：状态文件 `savedAt` 取秒级 UTC、`clusters` 按 key 升序、LF 结尾 ⇒ 可逐字节 diff；
  `hash` 只作短标识，**不参与判定**（截断 hash 有碰撞可能，一旦碰撞就会把不相关主题的历史当成本主题的）。
- **★ 实测（真实语料 48 条，站点 0 请求，连跑 3 次同一状态文件）**：

  | 运行 | 上次状态 | `Kidney`（stalled 5） | `调控` / `慢性`（resolved） | 建议检索式 |

  | 第 1 次 | `none` 首次 | `new` · 报过 1 | `new` · 报过 1 | 出 1 条式 |
  | 第 2 次 | `ok` 已合并 | `persistent` · 报过 2 ⇒ **抑制** | `cleared` · 报过 2 | **0 条**（显式注明「已抑制 1 个维度」） |

  ⇒ 第 1 次实测就把 `慢性`/`调控` 两条标成「回归」，报告凭空多出 2 条警示。
  真因：本次 status 也是 `resolved`（出现过又被消掉）等于**持续收敛**，不是回归。
  判据改为「本次**末轮仍在**」（status 不是 resolved/capped）。已落成断言（M6 变异可打红）。
  这条修正印证一点：**跨运行判据看的是「末态」，不是「出现过」**。

### 十七、修复：计数探针把「采集失败」当 0（静默缺陷 · 最佳档执行结果，2026-10-19）

- **动因**（「三」的挂账项）：2026-10-16 实测 10 条检索式探针里 **4 条** `reportedTotal` 为 `null`、

- **定性（决定了修法）**：站点真 0 条时给的是「约 0 条结果」（正则能取到整数 **0**）或

- **修法**：新增 `scripts/lib/probe.cjs`（纯函数，零 IO / 零网络），三态穷举互斥：

  | 观测量 | 三态 | 含义 / 用途 |
  |---|---|---|
  | 整数（**含 0**） | `counted` | 站点明确回答；0 属**有效证据** |
  | `null` + 页面明确说无结果 | `zero_confirmed` | 真 0，**可用于排除**该检索式 |
  | `null` + 无任何「无结果」提示 | `collect_failed` | **不得据此排除**，应重跑 |

- **失败三处可见**：`summary.json` 的 `probe.failed` + `warnings`（逐条点名、写明「不是 0 命中 / 不得据此排除」、
  并带实测耗时与当前 `--ready-timeout`）、事件流 `probe_collect_failed`、PRISMA 表「站点报告命中」列
  渲染为「**未读到**」（旧版与真 0 同为「—」，不可辨）。
- **顺带纠正一处假阳性**：exit 5（站点疑似不可用）原判据是 `reportedTotal != null`
  ⇒ 站点**明确**回答「0 条」时也会被判成站点不可用。现判据 =「全 0 抓取 **且** 站点一个读数都没给（含明确无结果）」。
- **接线可验证**（不靠正则猜源码）：把「写进 summary」收成 `attachProbe()`，单测用**真实对象**断言告警
  真的落到 `summary.warnings`、`probe` 字段真的登记。
- **闸门**：**307-0**（+15 项）。**变异 14 条全红**：M14 首轮 GREEN（断言选的反例里另有计数证据，
  掩盖了 `retrieved` 取值源错误）⇒ 补「有记录但无计数」反例后转红；另有一处**源码守卫自身写错**
  （正则在 `noResultSrc).test(t` 处要求无括号相邻）⇒ 基线恒假失败，由变异轮暴露并改为按语义位置匹配。

### 一、修复：翻译失败被记成「站点译文=是」

| 观测 | 值 |
|---|---|
| 面板实际文本 | 原 dump 三行：`✦ AI 翻译 · 中文` / `翻译失败` / `重试` —— 站点**自己**渲染的失败态（面板文本仅 20 字） |
| `/api/ai/translate` | **429**（连续重试 4 次均 429） |
| `/api/proxy/html` · `/api/scholar/annotate` | 200 · 200（**检索链本身完全正常**） |
| `/api/auth/me` · `/api/auth/refresh` | 401（匿名会话，预期） |

`clickTranslate()` 旧实现只 `waitForFunction` 等 `[class*="wl-ai-surface"]` **元素出现**，随后即 `return true`
—— **面板显示「翻译失败」时照样返回 true**。这不是命名歧义，而是**动作级标志对失败态的假阳性**：
把「翻译**尝试**已发起」当成「站点译文**已取到**」，因此**无法区分**「翻译成功但抓取漏了」与「翻译本身失败」。

**修法（两层分离 —— 权威真值不绑死在站点文案上）**：

| 层 | 载体 | 语义 |
|---|---|---|
| **权威真值** | `lib/extract.cjs::hasSiteTranslation(rec)` | 记录级：该条**是否真的带译文**（只看有无 `titleZh` / `abstractZh`）。站点改文案**不会**把它变成误报 |
| **动作诊断** | `lib/extract.cjs::classifyTranslatePanel(texts)` | 面板文本分类：`ok` / `partial_failed` / `all_failed` / `no_panel`；另 `no_button` / `panel_timeout` / `panel_unreadable` |

- `clickTranslate()` 返回值由 `boolean` 改为 `status` + `panels` 两字段对象；**回读触发条件不变**
  （仅 `no_button` / `panel_timeout` 不回读）⇒ 不减少任何一次回读，只纠正「把它记为成功」这一判定（**功能零删减**）。
- 记录字段：`translatedBySite` 改取**记录级真值**；新增 `translateStatus` 诊断字段。**CSV schema 未增删列** ⇒ 下游零破坏。
- 聚合：`summary.keywords[kw]` 与 `diagnostics.runs[]` 由「取 `records[0]` 单条代表整批」
  改为 `some(hasSiteTranslation)` + `zhTranslated` 计数。
- **失败必须有声音**：整批 0 条译文时写入 `summary.warnings`，并区分两种原因 ——
  「翻译面板已出现但未解析出译文结构（疑似站点面板改版）」与「站点 AI 翻译未取到译文（translateStatus=…）」；

- `PRISMA.md`：翻译失败原因出现在「**异常**」列（如 `translate:all_failed`），**不再静默**。

## [v4.2] — 2026-10-12 — 去重键重构（★ 修掉一条**数据丢失**路径）

### 背景（A2 原登记项 + 本轮实测新增）

原登记写的是「去重键三段不等价，估 <5%，**只多一条、不产生数据错误**」。
本轮运行时取证**推翻了这个评估** —— 实际是 4 项，其中一项方向**相反**（少多条）：

| # | 缺陷 | 实测复现 |
|---|---|---|
| ① | 年份单侧缺失 → 漏去重 | 键 `t:…\|y:1993` 与 `t:…\|y:` 不同 → 同一篇判为两篇 |
| ② | 第三段 `\|\| ('t:'+标题)` 是**死代码** | `'t:x\|y:'` 恒为真值 ⇒ 兜底层从未执行过 |
| ③ | DOI 未归一化 → 漏去重 | 大小写 / `https://doi.org/` 前缀 / 末点 **三种形态全部漏** |
| ④ | **标题为空 → 数据丢失** | 键退化为 `t:\|y:` ⇒ **3 篇真实论文被塌成 1 篇**（`unique=1 dup=2`） |

④ 是真路径而非理论：标题填充率守卫 `--fill-min` 默认 0.9，**允许最多 10% 空标题**；
50 条里出现 5 条空标题仍会通过守卫，随后被塌掉 4 条 —— **丢的是数据，不是多一条**。

### 修法（档 1：完整重构）

- 新增 `normalizeDoi()`：小写 / 去 `https?://(dx.)?doi.org/` 前缀 / 去 `doi:` scheme / 去末尾点 / trim。
- 新增 `dedupeTag()`：既无 DOI 也无标题时返回 `null`。
- `dedupe()` 由「单一 `\|\|` 键」改为**并查集连通**：
  ① DOI 与标题**双向互链**（避免「有 DOI 的一条」与「无 DOI 的同标题一条」对不上）；
  ② 分量内若存在**已知且不同**的年份 → 按年份拆分（防把同名不同年的真文献误删）；
  ③ 无可判定标识的记录**不参与去重**（宁可重复，不可丢失）。
- 返回值新增 `skipped` 字段（不参与去重的条数），便于可观测。
