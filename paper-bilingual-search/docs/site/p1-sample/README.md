# P1 交付样本 · 综合归纳 + 元典站点包（v4.12）

两件事的交付物：**报告多了一节「综合归纳」（大纲优先、每句挂行号）**，
以及 **一套把产物打成站点包的工具**（自包含、可校验、不猜站点路径）。

## 文件

| 文件 | 说明 |
|---|---|
| `report-sample.md` | assemble 的完整报告：综合归纳 → 证据分布图 → 候选表 → 逐条明细 |
| `pack/index.md` | 站点页（frontmatter + 警示 + 报告正文），**先看这个** |
| `pack/manifest.json` | 机器可读清单：sha256 / 统计 / 收录前 checklist |
| `pack/moc-entry.md` | 挂到 MOC 的一行（本工具**不直接改 MOC**） |
| `pack/README.md` | 收录步骤（给以后接手的人） |
| `pack/charts/*.svg` | 三张分布图（直接从源目录复制，不重绘） |
| `build-sample.cjs` | 可复现：`node build-sample.cjs` |

## 数据性质

**拟真夹具，不是真实检索产物。** 10 条记录，形状按 2026-10-21 实测复刻，
刻意包含三类必须被归纳说破的情形：

1. **A 档但物种是体外**（`[#2]`）—— 归纳必须写「不能按 A 档对待」；
2. **年份缺失两种形态**（`null` 与 `n.d.`）—— 都必须进「未标注」，不落入任何年份段；
3. **D 档三种成因**（设计未识别 / 已判定但薄弱 / 文本过短）—— 必须分组挂行号，不能合并成一个数。

## 综合归纳的六节

| 节 | 回答什么 | 硬约束 |
|---|---|---|
| 一、证据强度 | A/B/C/D 各多少 | 四档占比用最大余数法**凑满 100%** |
| 二、宣称可用性 | 有没有能支撑宣称的候选 | `needsReview` 全 true 时**必须说破** |
| 三、物种与设计风险 | A/B 档里哪些站不住 | 为零时写「无」，并说明这是**检查过且为空** |
| 四、时间分布 | 证据新旧 | 缺失年份**不进任何段** |
| 五、需人工优先处理 | 复核标记落在哪几条 | 无标记时说明「没标记 ≠ 没问题」 |
| 六、证据缺口 | 工具能如实说出的「不知道」 | 每个计数都挂行号 |

**每句挂行号**：凡含「N 条」的条目必带 `[#n]`，指向候选表的第 n 行（超过 5 条折叠成 `[#6]–[#20] 等 15 条`）。
本样本共 **46 处**行号引用。这条不是排版偏好 —— 没有行号的句子，读者只能选择相信或不信。

## 站点包的三条纪律

1. **状态写进 frontmatter**（`status: 候选未确认`）：站点全文检索索引的是这一段，只写在正文里，检索片段里就看不到。
2. **幂等**：产物不含 `now()`，时间一律取 `summary.json` 的 `startedAt` —— 否则同一份输入每次打包指纹都变，sha256 就没法判断「内容有没有真的变」。
3. **不猜站点路径**：本机没有 `vault/40_Maps`，所以工具只产挂载片段，绝不直接写 MOC。MOC 归属是人工判断，脚本猜错会把页面挂到不相干的主题下。

## 本轮抓到的问题

| 问题 | 性质 |
|---|---|
| `aTarget` 声明在 `if` 块内、`stats` 在块外引用 ⇒ 整个归纳章节崩成一行警告 | 真 bug（报告里只留警告，靠端到端才发现） |
| 四档占比 25+13+25+38 = **101%** | 真 bug（读者一加就能发现） |
| 排序比较器 `(y.year \|\| 0) - (x.year \|\| 0)` 遇 `n.d.` 得 **NaN** ⇒ **2019 排到 1998 之后** | **既有 bug**，P1 才暴露 |
| `md.includes('### 二、宣称可用性')` 用数组做子串匹配（`Array.includes` 是精确比较） | 判据写错 |

最后一条尤其值得记：标题恰好等于整个元素时"碰巧通过"，带括号的那节就挂了 ——
**判据在样本上通过，不等于判据写对了**。
