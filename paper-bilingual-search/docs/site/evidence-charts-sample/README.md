## 数据性质（重要）

**拟真夹具，不是真实检索产物。** 分布形状（A 2 / B 5 / C 8 / D 54）、年份跨度（1998–2026）、
物种构成按 2026-10-21 的实测形状复刻，只为把三条边界情形一次摆出来：

1. 全候选（`needsReview` 恒 `true`）—— 斜纹 + 警示带；
2. 年份缺失（`null` 与 `n.d.` 并存）——「未标注」列与「非法」分别登记，都不当 0；
3. 跨度 29 年 —— 触发「>14 年按 5 年分段」路径，脚注声明「段内合计」。

文件名与真实运行完全一致（`charts/evidence-grade-dist.svg` 等），因此可直接替换比对。

## 两条独立校验

```bash
node build-sample.cjs                 # 生成 6 个 SVG（含 JS 侧 geomCheck）
python check-svg.py                   # 独立复核：换语言、换解析器、换估宽方式
```

JS 侧 `geomCheck()` 与出图模块同源；`check-svg.py` 用 `xml.etree` 严格解析、按 Unicode
东亚宽度估宽，只求「两条独立路径都通过」。两条都做过**注入坏样本证伪**：

| 判据 | 注入方式 | 结果 |
|---|---|---|
| S1 严格 XML | 文字里塞裸 `&` | ParseError，报行号列号 |
| S3 rect 越界 | `x="24"` → `x="880"` | 报 `[880,76 852x42] 画布 900x352` |
| S4 文字越界 | 副标题注入 160 字 | 报 `[24.0,2250.4] 画布 900` |
| S6 字面量泄漏 | 分别注入 `<title>` / `text` / `aria-label` | 三处全部报出 |

> S6 初版只查 `<text>`，注入恰好落在 `aria-label` 上时**没报**——这就是「检查器本身必须被证伪」的实例：
> 不注入坏样本，永远不知道它漏了哪一类。

## 三件事只有「真的看一张图」才发现

机检全绿之后，我用 Edge headless 截了图逐张看，抓到六个问题（全部已修，见 CHANGELOG v4.11）：

| 问题 | 机检能抓到吗 | 说明 |
|---|---|---|
| 脚注写「D 档成因分解」，实际统计的是全体记录（46+23=69，而 D 只有 54） | 不能 | 已加不变式「D 档成因之和 = D 档计数」 |
| Y 轴刻度 0/7/14/21/28（`ceil(v/4)` 的副产物） | 不能 | 改为 1/2/5×10ⁿ，同一数据变成 0/10/20/30 |
| A(#1a7f37) 与 B(#57ab5a) 在 20px 堆叠段里几乎同色 | 不能 | A 改 #0f5132，并去掉 0.35 透明度（淡色会把两色压成一致） |
| 副标题里的 `**强调**` 被原样显示 | 不能 | SVG 不解析 Markdown，已加判据禁止图内出现 `**` 与反引号 |
| 热力格按全局归一致使「条数少」被读成「关系弱」 | 不能 | 改按行归一，副标题说明行内比色、行间比数 |
| 图② 列合计数字与图例挤在同一水平线 | 不能 | 图例下移 14px |

**结论**：几何校验保证「不越界」，只有人眼保证「可读」。两者不能互相替代。
