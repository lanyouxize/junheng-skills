# 中文轮次模板

用中文做拷问时读本文件，目的是降低中文用户的阅读与作答成本。
**本文件不改变 `SKILL.md` 的机制**——还是同一套决策树、前沿（frontier）、轮次与 `❓` / `➡️` 格式契约，只是换成中文措辞。

---

## 轮次骨架（照抄即用）

```
本轮 3 个问题，答完我重算前沿、再发下一轮。

❓ **Q1 - 首屏放几张图**：候选是单张主图（快、省事）和三图轮播（信息全、要维护）。
   目前还没有第二个卖点可放。

➡️ 建议单张主图。理由：现在没有可轮播的第二张素材，先不承担维护成本，等有素材再改。

---

❓ **Q2 - 数据存本地还是云端**：本地省一个后端，但换设备就没了。

➡️ 建议云端。理由：你已经提过要"手机上也能看"，本地存储满足不了，这是硬约束不是偏好。
```

**首行那句「本轮 N 个问题」是可选的**——只为让用户建立预期，不影响机制。

---

## 问题措辞：让「是」等于采纳推荐

上游要求 `Word each question so "yes" accepts your recommended answer.` 中文里最容易在这里翻车。

| ❌ 开放式（推荐被淹没） | ✅ 让「是」即采纳 |
|---|---|
| 「缩略图用 1x 还是 2x？」 | 「缩略图用 2x（Retina 才不糊）——可以吗？」 |
| 「你觉得要不要加缓存？」 | 「先加一层内存缓存，可以吗？」 |
| 「列表分页还是滚动加载？」 | 「列表用滚动加载，可以吗？」 |

判据：用户回一个「是 / 好 / 行 / 可以」，就等于采纳了你的推荐。**做不到这一点的问法要重写。**

---

## 推荐的两态（措辞必须不同）

每个问题都带 `➡️`，但推荐**不是**偏好。有没有依据，措辞要分开，否则会把自己的口味锚成用户的选择。

| 态 | 触发 | 中文措辞 |
|---|---|---|
| **有依据的推荐** | 存在项目既有约定 / 用户明说过的优先级 / 明显更安全或更省的做法 | `➡️ 建议 X。理由：<一句话依据>。` |
| **无依据的默认值** | 纯口味，没有可依据的东西 | `➡️ 默认 X——这只是默认值，不是推荐，我没有依据。你来定。` |

**推荐里若藏着"这个问题本身不该这么问"，要说出来。** 用户答「是」可能就是否定这个问题——他需要知道这一点。
例：`➡️ 建议先别做这个功能。理由：它服务的是你不打算做的那个场景。`

## 边界场景的中文话术

对齐 `references/boundaries.md` 的八类。**这些话术只是把同一条规则说成中文，不是新规则。**

| 场景 | 中文话术 |
|---|---|
| 光靠聊定不下来 | 「这个问题继续问也问不出来。我做个能点的原型给你看，看完你一句话就能定。」 |
| 会话越滚越长 | 「范围太大了，硬问下去只会越来越糊。建议把它拆成几块，分开拷问。」 |
| 上下文变长、后轮开始自相矛盾 | 「后面的问题开始跟前面的打架了。先把已定的梳理一遍、把还没定的列出来，你决定是收尾还是重开一轮。」 |
| 没有依据作推荐 | 「这个问题我给不了真推荐，只能给个默认值，你来拍。」 |
| 用户说「你帮我定」 | 低风险：「行，那我按 X 和 Y 两个假设往下走，不复述了。」<br>高风险（不可逆 / 对外可见 / 代价大）：「只有这一条我得再问一次——<问题>。其余的我按默认走。」 |
| 「一次一问」 | 「好，后面我一次只问一个。」（说一次即可，全程照办） |
| 用户嫌问得浅 | 「收到，这条我下轮往下钻一层。」 |
| 用户说范围跑偏了 | 「我把树重新切一遍，说明我砍掉了哪些。」 |
| 用户答「不知道」 | 「这算一个真答案。这条多半不是缺信息，是得先看到东西才能定——建议先做原型。」 |

## 收敛语（前沿空了时）

不要自动开工。用这个结构收尾，然后停住等确认：

```
共识梳理：

- **目标**：<一句话>
- **已定**：<关键决定，逐条>
- **未定**：<确实还没定的；没有就写"无">
- **下一步建议**：<一个动作>

确认没问题我再动手。
```

**「未定」不要留空话。** 真没有就写「无」——那句话本身就是「已达成共识」的证据。
